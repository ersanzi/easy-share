## 二、片 A：租户服务发现（本轮架构级改进）

**设计动因**（用户拍板方向）：同一租户内，客户端只应预知**一个**地址（控制面，构建期烧录），其余服务拓扑（知识服务、将来的服务）登录后统一从控制面拿。服务器换 IP、加服务都不用重新发安装包。对象存储不在此列（P2 起预签名 URL 逐次签发，客户端从不持地址）；AI/向量化配置是知识服务端的事，不进客户端下发范围。

**实现**（Java-first，最小闭环）：

- **控制面** `ServiceConfigController.java`（`/easyshare/service/config`）：GET 登录即可读、PUT 仅 superadmin。存储**复用 RuoYi sys_config**（键 `drive.service.knowledge.url`）——零新表、零 DDL、部署免迁移；读写走模块内投影（`SysConfigRow` + `SysConfigRowMapper`），不经 RuoYi 配置缓存，两边口径自洽（RuoYi 后台改、客户端管理页改，互相即时可见）。
- **客户端** `internal/account/serviceconfig.go`：`ServiceConfig`/`SetServiceConfig` + `DeriveKnowledgeURL`（推导回退：控制面 `:8090` → 同主机 `:8000`，剔路径/scheme 校验，`scheme` 缺失拒推）。
- **App 绑定** `ServiceEndpoints`（registry/derived 双来源标注）与 `SaveServiceConfig`；Wails 级联完整（generate module + types + services）。
- **前端**：「知识」页未配置时自动填服务器地址 + 预填当前登录账号（员工只差输密码）；管理页「账号」Tab 新增「租户服务地址」卡片（管理员登记/清空，清空保存即回退推导）。
