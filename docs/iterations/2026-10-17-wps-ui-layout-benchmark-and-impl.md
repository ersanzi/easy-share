## 学到的五个关键设计

### 1. 悬停行内操作条（最有价值）

WPS 的列表在**未悬停时是干净的**——只有图标、名称、时间、大小。
鼠标悬停某一行的瞬间，整行高亮，并**在行内**浮出 `复选框 / 星标 / +标签 / 分享 / ⋯`。

设计原则：**动作跟着对象走**。用户的眼睛已经落在那一行上了，操作就该出现在那一行，
而不是让他把视线移回顶部工具栏。

对比我们改造前：每行**常驻** 预览/下载/分享/删除 四个按钮。
一屏 10 行就是 40 个按钮，噪声远大于信息量。

### 2. 排序是列头，不是工具栏下拉框

WPS 的列头直接就是排序控件：

```
全部类型 ▾                          最后修改 ↓   大小 ▾
```

点击列头切换升/降序，当前排序列显示方向箭头。**视线与操作在同一处**。

对比我们改造前：工具栏里一个 `<select>` 加一个 `↑/↓` 按钮，
用户得先在列表里看到顺序不对，再把视线移到工具栏，选字段、再切方向。

### 3. 用量常驻

`企业空间 86.87G / 3.92T` + 进度条，常驻在侧栏底部。
「我还剩多少空间」是用户最常问的问题之一，答案应当随手可见。

### 4. 列表终止标记

底部「没有更多了」——明确告诉用户到底了，
而不是让他怀疑「是不是还有没加载出来的」。

### 5. 内容源的三段式分组

```
[新建][打开]          ← 动作区，常驻顶部，最大视觉权重
最近 / 星标 / 共享      ← 快捷视图
云文档                 ← 分组标题
  我的云文档 / 团队文档 / 知识库 / 我的设备 / 标签 / 回收站
本地
  桌面 / 文档 / 下载 / 微信文件 / 浏览
常用
  工作台
[用量条]              ← 常驻底部
```

**回收站是内容源之一，不是独立页面**——这与我原先把它做成「顶部按钮 + 覆盖层」的层级不符。

### 三个实现细节（都不是随手写的）

1. **按钮保留在 DOM 里、用 `opacity` 隐藏，不用 `v-if`**：
   `v-if` 会让键盘用户（Tab 到不存在的按钮）和触摸屏（永远没有 hover）**够不着**这些操作。
2. **`focus-within` 同样触发显示**：键盘焦点进入该行时也要浮出，否则键盘用户看不到可操作项。
3. **`@media (hover: none)` 时一律常显**：触摸设备没有悬停概念，隐藏等于不可用。

## 明确不抄

| 不抄 | 理由 |
| --- | --- |
| 最左侧 6 图标轨道 | 那是 WPS365 平台级入口（云盘只是其一），我们单产品没有对应物 |
| 知识库 / 我的设备 / 标签 | 知识库我们有独立一级导航；设备管理是局域网能力；标签是后续数据模型的事 |
| 本地「桌面/文档/下载/微信文件」 | 那是 WPS 的本机文件聚合，与我们「局域网收件箱」定位不同 |
| 新建 Word/Excel/PPT | WPS 是文档套件，我们是传输/存储工具，没有编辑器 |
| 智能问答浮球 | 我们有独立「知识」页，不塞进网盘页 |

## 仍未做

1. **「全部类型 ▾」筛选**：需要先定义扩展名归类规则。
2. **内容源左栏**：会牵动 `App.vue` 一级导航，**必须先想清楚与现有「文件/知识/会议听记」的关系**，
   否则左侧出现两套导航。这是产品结构调整，不适合顺手做。
3. **星标 / 标签**：需先有数据模型（WPS 与钉盘都做成一等多对多实体，不是文件上的枚举）。
4. **子页面内部布局未采集**：回收站/团队文档内部长什么样没看（鼠标点击坐标不够可靠，
   自动点击会点到相邻项）。
