# Cloudreve 对标研究与 EasyShare 演进建议

> 研究日期：2026-07-25
> Cloudreve 基线：`0bb0ab833571d380153edd3529e01a7957b8b4ce`（2026-07-15，`fix(dbfs): thumbnail not generated for shared files (close #3495)`）

## 1. 研究目的

EasyShare 是消费级桌面文件传输与云盘工具，不是多租户 Web 网盘。本次对标的目标不是复制 Cloudreve，而是识别其中已经验证过的文件产品设计思想，优先迁移能改善桌面体验、可靠性和后续可演进性的部分。

本次结论：**学习能力边界与工作流分层，不照搬 Cloudreve 的多用户 Web 平台架构。**

## 2. 源码证据

研究基于以下 Cloudreve 代码与说明：

- `README_zh-CN.md`：多存储策略、并行分片上传、媒体元数据与标签搜索、分享过期、在线预览、WebDAV 等产品能力总览。
- `application/dependency/dependency.go`：依赖集中装配与能力提供者的边界。
- `service/explorer/viewer.go`：预览器选择、Viewer Session 与面向前端的能力响应。
- `pkg/filemanager/manager/viewer.go`：内容访问与预览会话的文件管理层实现。
- `pkg/filemanager/manager/thumbnail.go`：缩略图生成、读取与生命周期处理。
- `pkg/filemanager/manager/recycle.go`：回收站/软删除工作流。
- `pkg/filemanager/workflows/upload.go`：上传工作流与队列进度模型。
- `pkg/queue/`：后台任务、调度、进度和持久化边界。
- `service/share/`：分享访问、管理与响应模型。

最值得迁移的共同模式有五点：

1. 后端返回文件“能做什么”，前端不根据扩展名猜实现。
2. 元数据访问、内容访问、分享访问分开建模。
3. 内容 URL 使用短期能力凭据，不暴露长期认证信息。
4. 预览、缩略图、媒体元数据、上传工作流、任务队列分别分层。
5. 产品能力通过统一文件模型向不同入口复用，而不是为每个页面各写一套判断。

## 3. 能力矩阵

| 能力 | Cloudreve 基线 | EasyShare 当前状态 | 是否适合当前定位 | 建议优先级与迁移方式 |
| --- | --- | --- | --- | --- |
| 多存储策略 | 本机、从机、多家对象存储、OneDrive、S3 兼容 | 单一 RustFS/S3 兼容后端，连接参数面向产品默认值 | 暂不需要完整策略平台 | P2；保留 `objectstore.Store` 抽象，只在真实产品需求出现时增加适配器，不增加用户可见技术配置 |
| 分片/并行上传 | 产品说明明确支持并行分片上传，上传工作流与队列解耦 | 单请求流式上传，可显示实时进度 | 非常适合大文件场景 | **P0**；引入 Upload Session、分片清单、并发上限、Complete/Abort，前端只展示自动恢复状态 |
| 断点恢复 | 上传工作流和任务状态为恢复提供基础 | 进程/网络中断后需重传 | 非常适合桌面工具 | **P0**；持久化 upload session、对象 key、文件指纹与已完成分片，启动后自动校验恢复 |
| 在线预览 | Viewer Session 按文件能力选择预览器 | **本次完成**图片、PDF、限量 UTF-8 文本预览 | 高价值、低学习成本 | **P0 已落地**；继续坚持后端声明 `previewKind`，内容 URL 使用短期票据 |
| 缩略图 | 独立 manager 负责缩略图生成和读取 | 未实现，文件列表为通用图标 | 适合图片密集目录 | P1；按对象版本/ETag 缓存，列表返回 thumbnail capability，后台生成失败不得阻塞列表 |
| 回收站/软删除 | 独立 recycle 工作流 | 当前直接删除对象 | 消费级产品强需求 | P1；先做单用户回收站前缀/元数据索引、保留期和恢复，避免引入多租户权限模型 |
| 搜索/标签/媒体元数据 | 支持媒体元数据抽取，并可按元数据或标签搜索 | 仅对象列表，无索引 | 在知识平台和大量文件阶段有价值 | P2；元数据异步提取，搜索索引与对象存储解耦，先支持名称/类型/时间 |
| 分享生命周期 | 文件/目录分享，可设置自动过期；管理与访问分离 | 可创建分享链接，缺少记录、撤销与过期管理 UI | 适合当前定位 | P2；增加本地分享记录、撤销、过期状态，避免直接引入用户组/公开站点模型 |
| 多用户/权限 | 用户、用户组、多存储策略 | 本机单用户、Core 仅回环 | 当前消费级阶段不适合 | 企业平台阶段；由未来控制面承担账号、权限和审计，桌面 Core 不复制 Cloudreve 用户系统 |
| 后台任务队列 | `pkg/queue/` 统一任务、调度与进度 | LAN 与云盘任务模型仍分散，部分历史可持久化 | 适合上传、缩略图、同步、AI 解析 | P1；统一任务实体和状态机，先覆盖分片上传/下载，再扩展同步和知识处理 |
| WebDAV | 覆盖存储策略 | 本地共享与云盘驱动器均已有 WebDAV 入口 | 已符合产品定位 | 保持；WebDAV 是系统入口能力，不作为 UI 总状态开关，不直接承载预览认证 |

## 4. 本次迁移：安全在线预览

本次实现把“前端按扩展名决定如何打开”改为后端能力声明：

- `cloud.File.previewKind` 供列表决定是否显示“预览”。
- `GET /api/cloud/preview?key=...` 通过 `HeadObject` 校正真实元数据并返回预览能力。
- 图片/PDF 使用五分钟 HMAC 内容票据访问 `/api/cloud/preview/content`；长期 Bearer API Token 不进入 URL。
- 文本最多读取 1 MiB，仅接受 UTF-8，并通过 Vue 普通文本插值渲染。
- SVG 明确视为主动内容并拒绝内嵌。
- MIME 判断采用对象元数据、系统 MIME 数据和内置扩展名回退，避免依赖 Windows 注册表的一致性。

这套边界可复用于未来缩略图、媒体流和分享访问：调用方获得的是短期能力，不是对象存储凭据或 Core 长期 Token。

## 5. 演进顺序

### P0：可靠上传

1. 定义可持久化 Upload Session。
2. 基于 S3 Multipart Upload 实现分片、并发和完成/中止。
3. 通过文件大小、修改时间和抽样哈希识别可恢复文件。
4. 将上传进度从 UI 事件提升为统一任务状态。
5. 用故障注入验证 Core 重启、断网和单分片失败后的恢复。

### P1：删除可恢复、列表更直观、任务统一

1. 回收站/软删除、恢复与保留期清理。
2. 图片缩略图缓存及能力返回。
3. 上传/下载/缩略图/同步共享统一任务模型。

### P2：管理与检索

1. 文件名/类型/时间搜索，再扩展标签与媒体元数据。
2. 分享记录、撤销、过期管理。
3. 仅在业务需要时扩展存储适配器。

### 企业平台阶段

多用户、用户组、权限策略和审计进入独立控制面。EasyShare Core 继续负责本机能力、传输和缓存，不演化为 Cloudreve 式公网多租户服务。

## 6. 明确不迁移的内容

- 不在消费级桌面阶段引入用户组、配额、管理员后台和公开站点。
- 不让用户选择 S3 分片大小、预览器、字段 key 等技术参数。
- 不让前端持有对象存储凭据或把长期 Core API Token 拼入 URL。
- 不为对齐功能数量而同时实现 Office 编辑、音视频转码、离线下载等重型能力。
- 不把 Cloudreve 的服务端部署拓扑直接套入 EasyShare 双进程桌面架构。

## 7. 后续验收门槛

任何从 Cloudreve 借鉴的新能力都应满足：

1. 默认自动工作，不新增普通用户难以理解的配置。
2. 能力由 Core 声明，前端只负责呈现和交互。
3. 长期凭据不进入内容 URL、日志或前端状态。
4. 后台失败可重试、可观测，不阻塞基础文件列表。
5. Windows/macOS 系统入口与应用内入口复用同一业务边界。
