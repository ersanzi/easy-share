# 2026-10-20 · 知识引用阅读页（引用 → 原文 → 下载）

## 用户问题

知识问答已经能给出带引用的答案，但桌面端引用只有文件名、匹配度和一段摘要：

- 用户无法核对答案依据的原文，知识库的可信度停在“看摘要”；
- Word/Excel/PPT 在网盘里仍显示“暂不支持在线预览”，而知识库恰恰以这些格式为主；
- 产物体（`clean.md` / `document.json` / 原件）此前只验登录、不验文档归属，知道 `file_id` 就能读别人的文档。阅读页会把这条路径变成常规能力，必须先补齐判据。

范围明确：只做展示和下载，不做编辑、不做协同文档。TangleSDK 那条协同协议取证线不投入。

## 目标

- 知识问答里的每条引用可点，打开只读阅读页并高亮命中的正文块；
- 阅读页按 `document.json` 的结构化块渲染标题、段落、表格，并显示页码/工作表/幻灯片位置；
- 阅读页可下载入库原件；
- 产物体、阅读页、原件下载与 `/query` 共用同一套 owner / 部门 / admin 可见性判据。

## 非目标

- 不做在线编辑、批注、协同；
- 不做网盘“加入知识库”入口与知识库文档清单（下一片）；
- 不做像素级 Office 版式还原（不引入 LibreOffice/OnlyOffice）；
- 不把 Markdown 当 HTML 注入渲染（避免 XSS 面，也拿不到块级定位）。

## 设计决策

1. **阅读页直接渲染 `document.json`，不渲染 Markdown。**
   块模型自带 `id`、`type`、`text/rows`、`source`；前端用文本插值渲染，天然避开 HTML 注入，并可用块 ID 做引用高亮与目录跳转。`clean.md` 继续留在调试/驾驶舱使用。

2. **引用即定位。**
   `/query` 返回的引用已带 `file_id`、`version_id`、`block_ids`（`internal/knowledge/client.go` · `Context`）；阅读页按 `block_ids` 高亮，`source.page/sheet/slide/paragraph` 只用于展示位置标签。

3. **产物级可见性收口。**
   新增 `knowledge/app/rag/permissions.py` · `can_view_document`，语义与 `visible_doc_ids` 一致：owner 非空仅本人与 admin；owner 为空按 `visible_depts`；都为空全体可见；未登录保持历史行为。`knowledge/app/api/routes.py` · `_visible_manifest` 在 `artifacts`、`view`、`source` 三个人口统一调用。**注意 `visible_depts` 在 job/manifest 里是 CSV 字符串**（与 `es_file.visible_depts` 同表示），判据按 CSV 拆分，不能用列表或子串——否则部门 `1` 会误命中 `10`。

4. **原件下载走“知识服务 → Core → 桌面保存框”。**
   知识服务用 `max_source_bytes` 读取原件并回 `Content-Disposition`；Core 流式透传并解除 30 秒写超时；桌面 `KnowledgeDownload` 弹保存框后 `io.Copy` 落盘，避免把大文件塞进 Wails JSON 通道。没有走 RustFS 直签，因为知识服务的 `rustfs_endpoint` 在服务器上可能是回环地址，客户端不可达。

5. **放弃的方案。**
   - 客户端 docx/xlsx/pptx 渲染库：包体大、PPT 保真度差、仍要处理私有 URL；
   - 服务端 LibreOffice 转 PDF：部署重、转换失败面多，第一片先用结构化阅读视图，真有版式硬需求再加；
   - 把 `clean.md` 直接当 HTML 渲染：XSS 面与定位能力都更差。

## 兼容与迁移

- 新增知识服务端点：`GET /documents/{file_id}/versions/{version_id}/view`、`GET .../source`。
- 新增 Core 端点：`GET /api/knowledge/documents/{file_id}/versions/{version_id}/view`、`GET .../source`。
- Wails 新增 `KnowledgeDocument`、`KnowledgeDownload`，旧绑定签名未变；`wails generate module` 已重生成。
- 无 DDL、无配置新增、无端口变化。
- **行为收紧**：已登录但无权查看某文档时，`/documents/.../artifacts` 从原来的 200 变为 403；未登录（本地 lab、auth 关闭）行为不变。旧 Core + 新桌面端不受影响；新 Core + 旧桌面端只是多出两个未使用端点。

## 发布与回滚

- 本轮只改源码与测试，**未构建安装包、未重启本地程序、未动活栈**。
- 回滚：移除 Core 两条路由、知识服务两个端点与阅读页组件/入口即可；无数据迁移。
- 真机验收清单（录音结束后执行）：
  1. 知识页提问 → 展开引用 → 点一条 → 阅读页打开且命中块高亮；
  2. 长文档目录跳转、表格渲染、页码标签；
  3. 下载原件 → 保存框 → 文件可打开且内容一致；
  4. 用无权限账号点引用 → 提示无权查看而不是空白；
  5. 录音/听记功能不受影响（本轮未改会议链路）。

## 完成记录

- 已完成：知识服务视图/下载端点与可见性收口；Core 代理与 Wails 绑定；桌面阅读页、引用入口、下载；Python/Go/前端测试。
- 实现中抓到的两处权限边界（已修）：`visible_depts` 在 job/manifest 是 CSV 字符串，按子串判断会让部门 `1` 误命中 `10`；Go 客户端若把它声明成 `[]string`，部门可见文档的 `/view` 会直接 JSON 解码失败。现分别由 `can_view_document` 的 CSV 拆分与 `DocumentManifest.VisibleDepts string` 钉死，前后端测试各覆盖一处。
- 已知限制：
  - 阅读页是结构化正文，不保留图片与复杂版式；需要原样时下载原件；
  - 大文档一次性读取正文，暂无虚拟滚动；`max_source_bytes` 上限内可用；
  - 原件下载在知识服务侧按 `max_source_bytes` 整份读入内存后再流式回传，大文件会先等待；桌面端已改为先弹保存框再发请求，取消不占用远端流。后续可把 `ObjectStorage` 增加 boto3 流式读取就地优化；
  - 只覆盖已入库文档；网盘里未入库文件还不能直接阅读（下一片：入库入口收进网盘）；
  - 真机 UI 未点验。
- 下一步：网盘文件/文件夹“加入知识库”，用同一 `file_id` / `version_id` 调 `/documents/process`，并把入库状态回显到文件行；随后补知识库文档清单与失败重试。
