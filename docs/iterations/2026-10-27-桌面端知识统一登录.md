# 桌面端知识统一登录（SSO 免登）

> 承接[第二轮](2026-10-27-桌面端企业化整改-第二轮.md)明确留下的边界：桌面「知识」页登录知识服务本地账号，功能权限矩阵只对控制面 SSO 令牌生效，knowledge / meeting 两项在桌面端**只有入口显隐、服务端没有闭环**。本片把这条边界关掉：客户端账号登录后，Core 用控制面令牌自动登录知识服务，员工不再二次输入知识账号口令。

## 目标

1. 客户端账号登录 / 启动恢复会话 / 管理员改服务地址后，知识会话自动切换为统一登录，知识页直接进入已登录态。
2. 统一登录会话走控制面身份，知识服务的功能权限拦截因此对桌面端真实生效（关掉「知识问答」直接 403，不是藏入口）。
3. 失败必须可回退：知识服务没接统一登录（旧部署、未配置 `CONTROL_PLANE_URL`）时保持手动登录通道，不覆盖用户已有的知识会话。

## 非目标

- 不改知识服务本地账号体系：本地 `/auth/login` 保留（WPS 加载项、浏览器驾驶舱、admin 备用通道仍用它）。
- 不做 `/kapi/*` 令牌注入反代（tasks.md 里 P2「Core 知识网关泛化」的另一半，动桌面主链路，留待部署窗口）。
- 不处理运行期间控制面令牌自然过期后的自动续期（见「已知边界」）。

## 设计决策

### 1. Core 会话加 `mode`，注册端点先探测再落盘

- `knowledge.Session` / `StatusView` 增加 `Mode`：`password`（知识账号口令）、`sso`（随客户端账号）、空（未登录）。手动登录写 `password`，SSO 注册写 `sso`。
- 新增 `POST /api/knowledge/sso`（`internal/api/knowledge.go` · `knowledgeRegisterSSO`）：接收 `serverUrl` + 控制面令牌，先调知识服务 `GET /auth/me` 验证这张令牌**确实被知识服务接受**，成功才 `SignIn` 落盘。
  - 401 → `knowledge_sso_rejected`（知识服务没接统一登录，或控制面会话已失效）；
  - 网络/其他错误 → `knowledge_sso_unavailable`；
  - 两种情况都**不覆盖**本机已有的手动登录会话，知识页回落到账号口令登录。
- `knowledge.Client.Me` 是最小探测面：返回 username / role / dept，不落任何业务数据。

### 2. 桌面壳：登录态生命周期驱动 SSO 注册

- `App.syncKnowledgeAccess` = 先地址对账（`reconcileKnowledgeSession` 改为返回对账后应使用的地址），再 `registerKnowledgeSSO`。三处触发：账号登录成功、启动恢复会话、管理员保存服务配置。
- 新增 `knowledgeSyncMu` 串行化「注册」与「登出清理」：两者都跨进程改 `knowledge.json`，交错执行会让已登出的账号把知识会话重新登回去。
- 注册成功后再校验一次账号令牌：探测期间用户登出或换人则立即撤销刚登记的会话（知识会话不能比账号活得更久）。
- 登出、启动校验遇 401 时 `clearKnowledgeSSO`：**只清 `mode=sso` 的会话**，用户手动登录的知识账号不动。
- 成功/清理后统一 `EventsEmit("knowledge:session-changed")`，前端据此刷新登录态。

### 3. 同一地址的手动会话会被 SSO 接管——这是特性不是副作用

知识服务的功能拦截只对「解析出控制面身份」的令牌生效，本地账号不受矩阵管辖（`knowledge/app/main.py` 的注释即此口径）。若保留手动会话，矩阵在桌面端永远闭不上环。因此控制面已登录时，同一地址上的手动会话被 SSO 替换；仅当知识服务不接受控制面令牌（未接 SSO）时才保留手动会话作为回退通道。

### 4. 前端：标明会话来源，SSO 不提供「退出登录」

- `KnowledgeStatus` 增加 `mode`，Wails 绑定重生成。
- 知识页已登录栏给 SSO 会话打「统一登录」标记，隐藏「退出登录」按钮（退出客户端账号即失效，单独退知识服务没有语义）。
- 未登录表单在客户端账号已登录时提示：会先尝试自动登录；仍要求密码说明知识服务未接入统一登录或客户端登录已过期。
- 知识页、会议页订阅 `knowledge:session-changed` 刷新登录态与数据（会议页顺带重拉列表）。

## 已知边界

1. **运行期令牌过期**：账号会话只在启动时校验；控制面令牌过期后知识接口 401，Core 会清掉知识会话，但顶栏仍显示账号已登录，需要退出重登（或等下次启动校验）。若部署把 token TTL 设得很短，需要补周期性校验或 401 联动 `auth:expired`。
2. **SSO 注册不按 features 预跳过**：管理员后来开启某项功能时，员工无需重新登录（知识服务每次验票取最新 features）；关闭同理，由服务端 403 兜底。
3. **WPS 加载项与浏览器驾驶舱仍走本地账号**：它们不经过桌面壳，拿不到控制面令牌；统一登录只覆盖桌面端。

## 真机点验清单

1. 控制面、知识服务（配置 `CONTROL_PLANE_URL`）、客户端全部启动 → 客户端登录 → 打开「知识」页：直接是已登录态，标注「统一登录」，无密码输入框。
2. 管理员关掉该账号「知识问答」→ 知识页提问返回「该功能已被管理员关闭」；「会议听记」仍可用（若未关）。
3. 管理员关掉「会议听记」→ 会议页请求 403，提示来自服务端。
4. 知识服务未配置 `CONTROL_PLANE_URL` 时登录客户端 → 知识页仍显示手动登录表单，日志有 `knowledge sso register` 失败记录，手动知识账号可正常登录。
5. 客户端退出登录 → 知识页回到未登录（SSO 会话被清）；手动登录的知识账号不受影响。
