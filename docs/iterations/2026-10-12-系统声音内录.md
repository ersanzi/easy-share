# 迭代记录 — 会议听记·系统声音内录（Windows）（2026-10-12，用户直配轮第三片）

> 触发：听记切片交付后用户问「实时上屏与系统声音内录能做吗」，拍板顺序：
> 真实验收说话人分离（用户侧）→ **系统声音内录（本片）** → 实时上屏/思维导图后置。
> 内录与验收天然配合：录一场线上会，采集与分离一起验。

## 背景与目标

线下会议已有麦克风采集；线上会议（腾讯会议/钉钉里对方的声音）需要「系统声音内录」。
钉钉听记对应能力是音源选择：麦克风 / 系统声音。本片给听记页加音源切换。

## 方案：getDisplayMedia（前端复用管道），Go WASAPI 为后备

- **首选路线**：WebView2（Chromium）支持 `getDisplayMedia({video, audio})`——屏幕共享
  时勾选「同时分享系统音频」即可拿到系统声音 MediaStream 音轨，喂给**现有 recorder.ts
  管道**（AudioWorklet → 16k 重采样 → WAV → /kapi 上传），后端零改动。
  相比 Go WASAPI loopback（需 syscall 封装或引 go-wasapi）便宜一半以上。
- **决策门（spike）**：WebView2 弹共享选择器且能勾选系统音频、转写有真实内容 → 采用；
  被拦/无音频轨 → 后备改 Go 侧 WASAPI（go-wasapi，syscall 无 cgo）。
- **macOS**：WKWebView 不支持 getDisplayMedia——音源入口在 macOS 隐藏（系统声音内录
  在 macOS 本就无公开 API，维持不做清单）。
- 已知取舍：共享选择器每次录音会弹一次（Chromium 标准交互，用户选「整个屏幕」+
  勾音频）；video 轨拿到后立即 stop，只留音频。

## 实现

- `recorder.ts`：`start(source: 'mic' | 'system')`——system 走 `getDisplayMedia({video, audio, systemAudio:'include', selfBrowserSurface:'exclude'})` 拿系统音频轨；**video 轨保留到停止**（Chromium 里关 video 轨会连带结束共享会话）；音源节点显式下混单声道（系统声通常立体声）；音轨 `onended` 回调供 UI 自动收尾（用户点共享条「停止共享」时录音自动完成转写）；未勾音频/取消选择给出面向用户的错误文案。
- `MeetingsPanel.vue`：音源分段切换（麦克风/系统声音，macOS 隐藏系统声音）；选系统声音时显示操作引导文案；`onAudioEnded` 自动触发 stop。
- 样式：`meeting-source` 分段控件；文案与提示。

## 验证

- vue-tsc 干净、wails build 通过；本机真机 E2E（computer-use 驱动完整 UI 流程）：
  - 音源切换渲染 ✓；「开始录音」→ WebView2 原生共享选择器弹出（自带「使用系统音频共享」开关）✓；
  - **整个屏幕 + 系统音频**路线：录 127.6s（16k 单声道 WAV，峰值/RMS 确认真实信号）→ FunASR 转写 **9 轮发言、3 个说话人标签，内容与播放的测试音频逐句对应** → LLM 总结准确 ✓；
  - 错误路径：不勾音频共享 →「未勾选…没有拿到系统声音」提示 ✓；取消选择 → 友好提示 ✓；
  - `onAudioEnded` 自动收尾真实触发过一次（播放结束音频轨 ended → 自动上传转写）✓。
- 采样夹具二次利用：外放 `samples/meeting/meeting_test.wav`（双声部 TTS）走数字 loopback，声学损耗为零，是对说话人分离更公平的测试素材。

## 排障实录与已知行为

- **「窗口」模式 + 系统音频实测无声**（录到 74.9s 但全静音）：开关视觉确认 ON 仍无声，疑似 WebView2 窗口模式系统音频实现问题（Chromium 上游行为），未深究——**UI 引导文案已指向「整个屏幕 + 勾选系统音频」**，用户照引导走即避开。
- **列表视图不回 segments 字段**：排障时用列表接口看 `turns:0` 误判为无声，实际详情接口有完整转写——调试要打 `/meetings/{id}` 详情。
- 录音尾部有静音段属正常（手动停止晚于播放结束；自动收尾路径下不会有）。

## 边界与不做清单

- macOS 不提供系统声音入口（WKWebView 无 getDisplayMedia、系统无公开 loopback API，双重不做）
- 不做音量电平显示增强/共享会话状态持久化；每次录音弹一次共享选择器是 Chromium 标准交互，接受
- 实时上屏维持后置（等真实使用反馈）
