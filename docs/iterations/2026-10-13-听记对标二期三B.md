## 一、阈值是量出来的，不是拍的

模型复用已在用的 cam++（`iic/speech_campplus_sv_zh-cn_16k-common`，本机已缓存，输出 192 维 `spk_embedding`），无需新增依赖或下载。

用本机 3 条**真实会议录音**跑「按说话人切片 → 抽声纹 → 两两余弦」：

| 对照 | 实测余弦 |
| --- | --- |
| 同一真人、不同场次（3 条录音各自的说话人 0） | **0.863 / 0.887 / 0.907** |
| 同一场次内的不同人（最具对抗性：同信道同环境） | 0.394 / **0.482** |
| 不同场次的不同人 | 0.227–0.387 |

同人均值下界 0.863 与不同人上界 0.482 之间取中值 → **`MATCH_THRESHOLD = 0.67`**，两侧各留约 0.19 余量。另设取样门槛：某说话人累计语音 <3s 不抽声纹（结果不稳），单次最多取 20s（声纹不需要全场内容）。

## 二、实现

- **知识服务**：新增 `app/meetings/voiceprint.py`（`VoiceprintStore`：按 owner 隔离的 `data/voiceprints.json`，向量 base64 存、列表只回元数据、`recognize()` 逐簇取最像者、`remove()` 彻底删向量）。`service.py` 加 `initial_speaker_names`（重新转写时**保住用户改过的名字**，之前每次重跑都会把名字冲成默认值）、`apply_voiceprints`（只填仍是默认名的簇，不覆盖人工改名）、`rename_speaker`（改名即沉淀声纹；沉淀失败不影响改名本身）。路由 `GET/DELETE /meetings/voiceprints[/{name}]`
- **Go**：`MeetingVoiceprint` 类型 + 2 客户端方法 + 2 代理 + 2 路由 + 2 desktop 方法 + 2 绑定
- **前端**：「识别热词 / 声纹」折叠区里加「我的声纹（N）」列表与删除按钮，文案写明属个人生物特征、可随时删除

**为什么必须有查看与删除入口**：声纹是生物特征个人信息，"能自动认人"的能力一旦建立就不透明；不做可查可删等于偷偷留存。列表接口刻意不回向量本体。

## 三、实测（真实链路，全部在测试自建记录上跑）

13 项全过：

- 第一场转写出 2 位说话人 → 把说话人 0 改成「张三」→ 声纹表自动出现 `张三 / sample_seconds 35.1`，且响应体里没有向量本体
- 同一批音频的**第二场新听记**：`{'0': '张三', '2': '说话人 3'}` —— 自动认领成功，且**负对照成立**：不像的那位没被乱认
- 删除「张三」声纹后再跑第三场：`{'0': '说话人 1', '2': '说话人 3'}` —— 删除即时生效，能力真的收回去
- 清理还原：听记数回到 3 条、声纹表回到 0 条（你原有的 3 条记录全程未被改动）

**踩坑记录**：首轮验证误报"转写不完成"，实为等待预算不够——导图 harness 的多段 LLM 调用（经 mirasim 中转）让单场全管线跑到 3–4 分钟，把等待从 200s 放宽后即通过。不是缺陷，但说明**长会议的全管线耗时主要由 LLM 段而非 ASR 段决定**（ASR 本身 RTF 0.08）。

## 五、已知边界

- 只对**该用户自己的会议**（owner 隔离）生效，跨用户不共享声纹
- 说话人簇本身分错时（cam++ 聚类把两人并成一人），声纹会跟着错——这是分离质量问题，不是认领问题；改名仍可纠正
- 没做钉钉的「合并发言人 / 清除声纹 / 声纹策略文案」全套（轻口径刻意不做），也未做「已在 N 篇听记中识别」的计数展示
