# 2026-10-20 · 网盘下载应用内闭环

## 用户问题

用户原话：「下载文件，现在走的并不是平台内的功能，反而是浏览器的，这肯定不对，要在软件能体现，建议你看看 wps 和钉钉是怎么做的」。

`App.CloudDownload` 当时只做一件事：用控制面换一条预签名 GET URL，然后 `BrowserOpenURL` 把地址甩给系统浏览器。后果是一整条链路脱离应用：

- 应用里没有任务记录，用户点完「下载」后不知道有没有开始、下到哪、失败还是成功；
- 进度、速度、失败原因全部看不见，浏览器下载完也不会回到 EasyShare；
- 落点由浏览器决定，和设置页的「接收目录」没有关系；
- 下完没有「打开文件 / 打开所在文件夹」入口，用户还得自己去文件夹里翻。

WPS 云盘和钉钉桌面端的共同做法是：下载是**应用内的传输任务**，默认落到下载目录，列表里给进度，完成后给「打开」「打开所在文件夹」。本切片按这个模型收口。

## 目标

- 云端文件下载在桌面进程内完成，字节只经 `internal/drive` 的预签名 GET 流，不再打开浏览器；
- 默认落到设置页的接收目录，同名不覆盖，自动生成「文件 (1).ext」；
- 下载任务进入 Core 统一任务存储（`kind=cloud_download`、`direction=receive`），活动抽屉与传输列表可见进度、速度、失败原因；
- 点击下载后自动展开「活动」，让进度立刻可见；
- 右键菜单保留「另存为…」，走系统保存框，取消不创建任务；
- 完成后提供「打开文件」与「打开所在文件夹」；Windows 的「打开文件」必须真的用默认应用打开，而不是只选中。

## 非目标

- 断点续传、暂停/恢复、限速、批量下载队列（当前一次一个后台 goroutine，失败整条重来）；
- 下载目录按文件类型分类、完成后自动打开；
- 目录整体下载（当前目录行仍不支持下载，只下载文件）；
- WPS/钉钉的「下载完成气泡」；本切片用自动展开活动抽屉替代。

## 设计决策

1. **预签名 URL 只在本进程内使用。**
   `App.startCloudDownload` 调用 `Client.Open` 拿到 `io.ReadCloser` 与 `ContentLength`，之后由 `copyCloudDownload` 读流写盘。浏览器路径彻底删除。远端流**同步打开**：未登录、无权限、对象不存在这类错误立刻返回调用方，前端马上弹错，而不是让用户过一会儿在任务面板里发现一条失败记录。

2. **任务必须在创建时就带上 `localPath`。**
   `internal/task` 的 `LocalPath`、`FileName`、`TotalBytes` 在 `Create` 之后不可变（避免传输中被改写）。因此 `POST /api/tasks` 的输入结构新增 `localPath`，`App.startCloudDownload` 先算好最终路径，再 `CreateTask`，完成后只 patch 进度/状态。前端完成态按钮直接读 `task.localPath`，不需要再查一次本地目录。

3. **默认落点读当前持久化配置，而不是启动快照。**
   `App.downloadDirectory` 每次 `config.Load(a.configPath)` 现读 `ReceiveDir`；设置页刚改完目录，下一次下载立即生效，不会用到桌面端启动时的旧值。设置页文案同步从「接收目录」改为「接收与下载目录」，说明两类文件共用一个落点。

4. **文件名来自用户内容，不能直接拼路径。**
   `safeCloudDownloadName` 先 `path.Base` 取单段（阻断 `../` 穿越与带 `/` 的键），再把 Windows 禁用字符 `< > : " / \ | ? *` 与控制字符替换为 `_`，去掉尾部点和空格；空结果回落「下载文件」；`CON` / `NUL` / `COM1` 等设备名即使带扩展名也加 `_` 前缀。重名不覆盖：`uniqueDownloadPath` 生成「文件 (1).ext」到 `(9999)`，与 WPS/钉钉的落盘规则一致；「另存为」的落点由保存框确认，不再自动改名。

5. **先写临时文件，完成后再落位。**
   `os.CreateTemp(dir, ".easyshare-download-*.part")` → 写满 → `placeDownloadedFile` 改名。任一步失败都删临时文件并把任务标 `failed`，用户不会看到一个「看起来下载完了」的半截文件。Windows 的 `Rename` 不能覆盖已有文件，另存为确认覆盖时先移除旧文件再改名；下载失败时旧文件原样保留。

6. **进度节流但不省状态。**
   256 KB 缓冲读取；`total > 0` 时每 200ms patch 一次 `transferredBytes` / `speed` / `status`，完成时统一 patch `completed`、`speed=0`，并在已知总长时把 `transferredBytes` 对齐到 `total`。未知大小时不伪造百分比，任务仍会在完成时收口。

7. **本地错误也要有稳定错误码。**
   创建目录、建临时文件、写盘、关闭、落位失败统一 `driveerr.Wrap(..., driveerr.CodeLocal)`；`failTask` 原来会忽略显式传入的错误码、改用 `Classify` 重算，现改为「显式码优先」。同时补上 Core `PATCH /api/tasks` 此前**丢弃 `errorCode` / `systemCode`** 的缺口——不补的话，前端拿到的失败原因只有一句话，错误三件套在这一条链路上不成立。

8. **「打开文件」与「打开所在文件夹」是两个动作。**
   原先 `fsutil.OpenFile` 在 Windows 上是 `explorer /select,` —— 名为打开，实际只选中。现改为 `ShellExecute("open")`，真正交给文件关联程序；新增跨平台 `ShowInFolder`：Windows `explorer /select,`、macOS `open -R`。Wails 新增 `ShowInFolder` 绑定，活动抽屉与传输列表的完成态都提供两个按钮。

## 兼容与迁移

- Wails 新增 `CloudDownloadAs`、`ShowInFolder`，绑定已重生成（`frontend/wailsjs/go/main/App.*`），`services/core.ts` 同步封装。
- Core API 加法：`POST /api/tasks` 接受 `localPath`；`PATCH /api/tasks/{id}` 接受 `errorCode` / `systemCode`。旧调用方不传则行为不变。
- 无 DDL、无端口、无配置项新增；`ReceiveDir` 语义扩展到「接收 + 下载」，已有配置直接复用。
- 行为变化：下载不再弹保存框、不再打开浏览器；需要选落点时用右键「另存为…」（或后续可加入口）。
