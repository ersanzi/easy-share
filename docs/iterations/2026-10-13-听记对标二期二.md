## 四、取舍与实测坑

- **为什么不上 WebSocket**：钉钉用长连接是因为它要跨端下推服务端事件；我们的推流是「采集端主动供数据」，请求-响应天然带背压，还避开 WebView 跨源、`/api/events` 令牌不能进前端这两件事。代价是每片一次往返（~176ms），实测无感
- **冷加载必须预热**：首片实测**卡 74.3 秒**（torch 导入 + GB 级权重）。解法是进听记页即调 `stream/warm` 后台加载；本机预热约 24s，预热后首片 150ms。用户若在页面打开后 24s 内就按录音，首片仍会等——已接受（后续说话照常出字）
- **实时文本质量低于离线**：流式模型出现叠字（"知识识库"），因此实时只做预览、不当结论；停止后整段离线重跑覆盖 `segments`，说话人与标点仍以离线为准。口径上前端明确写了「终态以录制后的完整转写为准」
- **`chunk_size` 必须是 `[左,当前,右]` 列表**：传 int 会炸在 `init_cache`（`'int' object is not subscriptable`）；片长 = `chunk_size[1] × 960` 样本
- **又踩自己记过的坑**：改完 Go 只跑 `wails generate module` / `wails build` 会得到**旧的 `easyshare-core.exe`**，新路由直接 404。必须显式 `go build -o build/bin/easyshare-core.exe ./cmd/core`（AGENTS.md 已记，本轮第四次复现）
