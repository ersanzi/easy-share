# 迭代：会议纪要引擎独立成通用工程（minutecraft）+ 钉钉版式导出

> 时间：2026-10-18　触发：用户先指出「思维导图、图文海报和钉钉有差别」，随后给两份钉钉原生导出件对照；
> 看过之后拍板「把录音文档 → 会议纪要做成通用性工程，方便后续复用与单独维护，后面丢给 WorkBuddy / DeepSeekHarness / Codex 这些 Agent 也能用」。
> 口径确认：拆分形态 = **独立 CLI + Python 库**；落点 = **本仓顶层 `engine/`**；依赖口径 = **「这里只要转写后的文本」**（即引擎不做 ASR）。

## 1. 为什么之前"不像钉钉"（问题定位）

对照用户提供的两份钉钉导出件（`纪要_09-09 …pdf` 6 页 / `纪要_06-25 ….pdf` 8 页），逐页渲染后确认差别不在字体，而在**产物形态与版式结构**：

| 维度 | 钉钉 | 我们（改造前） |
| --- | --- | --- |
| Word/MD 导出 | 封面「可视化报告」：01-06 带序号 + 玫红/蓝/青/琥珀/绿 色卡模块，卡片 = 色块标题 + 状态标签 + 要点 + 底色小结条 + 页脚水印；文档体有 AI洞察、待办方框、章节（时间戳）、核心发言提炼（原话引用）、全局行动项三列表格 | 标题 + 纪要段落 + 项目符号，一眼就是"程序拼的" |
| 图文海报 | 独立产物（E22 可视化报告） | 只有 5 套换配色的长图皮肤 |
| 总结内容 | 洞察 / 核心发言 / 章节概述 都在总结里 | 只有 minutes / key_points / chapters |
| 思维导图 | 真正画出来的图 | 自绘嵌套列表（markmap 白屏后降级） |

**结论**：观感差距的 80% 来自「有没有结构化字段 + 有没有按结构排版的导出器」，20% 来自字体。先把前者补上，性价比最高。

## 2. 本片交付

### 2.1 总结侧新增三个结构化字段（`summarizer.py`）

- `visual`：汇报卡结构 —— `{summary, sections[{title, layout, items[{title, tag, bullets, note}]}]}`，
  `layout` 取 `cards|duo|flow|list|closing`，色带 `accent` 由后端轮转（01/05 同玫红，与钉钉一致）
- `insights`：AI 洞察 2-4 条（转写里没明写的判断与风险）
- `quote_kp`：核心发言提炼 `{speaker, points[], quotes[]}`，quotes 要求逐字
- 解析全部带归一与兜底：`_parse_visual / _parse_insights / _parse_quote_kp`，非法形状返回 None 不抛错

### 2.2 钉钉版式 Word 导出（新增导出器）

两页式结构（实测复刻，不靠猜）：

1. **封面**：24pt「纪要」→ 12pt 主题/时间/参与人（悬挂缩进，折行对齐）→ 18pt 标题 → 灰色一句话主题 → 细分隔线 → 01-06 色卡模块 → 页脚水印
2. **文档体**：18pt 青绿章节标题 + 两级项目符号（· / ○）→ AI洞察 → 待办（☐ 方框）→ 章节（`00:06:00 标题` + ○ 概述）→ 核心发言提炼（观点 + 灰斜体原话）→ 全局行动项汇总（三列表格）
3. **附页**（可选）：转写全文

排版实现要点：颜色走 run 级 hex（`_set_run` 同时设 `w:eastAsia`，否则中文回退主题字体）；卡片用无边框表格 + 单元格底纹；小结条用段落底纹。

### 2.3 前端汇报卡预览（`MeetingVisualReport.vue`）

794×1123（A4 @96dpi）版式，与 Word 同一套色带和结构；补上 `flow`（左右进程 + 箭头）与 `closing`（满宽共识条）两种 layout。图文海报弹窗新增 `report` 主题并置于首位，默认选中。

### 2.4 通用工程化（本片重点）

顶层新增 `engine/`（包名 **minutecraft**，`pip install -e engine` 可独立安装）：

```
engine/
  pyproject.toml           # 内核依赖只有 openai / httpx / python-docx；[asr] 为可选附赠
  README.md                # 快速开始 / 输入格式 / CLI / Python 库 / 产物结构 / Agent 接入提示
  minutecraft/
    __init__.py  cli.py  __main__.py
    models.py              # Transcript / TranscriptTurn + SCHEMA（机器可读自描述）
    transcript.py          # 纯文本 / SRT / JSON 记录 / stdin 归一
    engine.py              # MinuteEngine 门面：一次 build 产出 summary+todos+keywords+mindmap+files
    summarizer.py          # LLM 结构化产出（含新增 visual/insights/quote_kp）
    mindmap_harness.py     # 三阶段导图管线
    templates.py           # 7 个内置模板
    docx/{__init__,export,visual}.py   # 钉钉版式导出 + 汇报卡结构（前端共用口径）
    asr.py                 # 可选：手上有 wav 时顺带转写（_asr_impl.py，需 [asr]）
  tests/test_engine.py     # 13 例，全离线
```

**边界**：引擎只吃**转写后的文本**（用户拍板口径）。ASR 留在采集端（知识服务），符合「采集与编排属产品态」的判断。

**Agent 接入面**（WorkBuddy / DSH / Codex）：

```bash
minutecraft schema --json        # 先自描述，Agent 不必猜字段
minutecraft run meeting.srt --out out/ --json
# 退出码：0 成功 / 2 输入无法解析 / 3 LLM 或生成失败
```

**知识服务改薄壳**：`app/meetings/{engine,summarizer,templates,mindmap_harness,docx_export}.py` 全部改为转发到
`minutecraft`，实现只剩一份。薄壳里 `sys.path` 注入 `engine/`，因此**不装包也能跑**；想隔离依赖可 `pip install -e engine`。

## 3. 过程中踩到并修掉的坑

1. **Word 封面后多出一整页空白**：`document.add_page_break()` 在段落里插裸 `<w:br type="page"/>`，
   再加一个空段就叠出一页。改为「空段 + `pageBreakBefore`」，4 页 → 3 页。
2. **卡片太高把封面顶到第二页**：单元格默认上下内边距 0.19cm × 2 + 行距 1.35 → 收到 0.05cm、1.3 倍后一页放下。
3. **closing 卡出现一个孤零零的色块**：无标题时卡头仍渲染 ▮。改为有标题/标签才渲染卡头。
4. **测试 monkeypatch 失效**：`knowledge` 侧原先 `from app.meetings.mindmap_harness import build_mindmap_harness`
   在函数内绑定，测试 patch `app.meetings.mindmap_harness` 无效 → 改为 patch `minutecraft.mindmap_harness`（与 service 同一模块）。
5. **PowerShell `Add-Content` 写中文进 style.css 变成乱码**：改用 edit 工具写入，并回滚错误行。
6. **LLM 端点间歇 429**：真实 E2E 连续三次撞 `429 insufficient_quota`。给引擎加了**可重试退避**
   （429/5xx/连接类，指数退避，默认 4 次、基数 3s，可用 `MINUTECRAFT_LLM_RETRIES` / `MINUTECRAFT_LLM_RETRY_BASE` 调），
   非可重试错误（400/401/404）立即失败。这是 Agent 跑在别人额度池上最常见的问题，必须内建。

## 4b. 续做：思维导图改回真图（同日，用户「继续」）

上一轮把导图列为遗留项。续做这一轮的目标很明确：**把 2026-10-12 那次 markmap 白屏查清并修掉**，
而不是继续用自绘嵌套列表凑合。

### 根因（三条，缺一条就是空白）

1. **SVG 没有确定的像素尺寸**——放在 flex 容器里 `height` 落到 0，markmap 算出 NaN 坐标，画出来就是白；
2. **必须在挂载后下一帧再建图**——容器还没进 DOM / 未布局时测到的尺寸是 0；
3. **数据要经 `Transformer.transform` 转成 `{ data }`**——不能把 markdown 直接塞给 `Markmap`。

`components/MindMap.vue` 用「tick → 测量宽度 → 建图 → fit」的固定顺序把三条钉死，并**不吞异常**：
渲染失败会把错误文案显示在画布上（当初只看到一片白，就是因为异常被咽了）。

### 测试侧另外挖出的四层坑（值得记，都会再次遇到）

| # | 现象 | 真实原因 |
| --- | --- | --- |
| 1 | `ResizeObserver is not defined` | jsdom 没实现；老 WebView 也可能缺 → 组件内垫了 no-op 降级 |
| 2 | `Cannot read properties of undefined (reading 'baseVal')` | d3 过渡插值要读 SVG `transform.baseVal`，jsdom 没有 SVG 布局引擎 |
| 3 | 桩打上去**不生效** | vitest 的 jsdom 环境把 `SVGElement` 垫成中间类，节点真实构造函数是 internals 里的 `SVGGElement`（`node.constructor === window.SVGElement` 为 false）→ 必须先用 `createElementNS` 拿到真实构造函数再打桩 |
| 4 | `import('markmap-view')` 的 Promise 不 resolve | 测试环境里动态 import 被外部化挂住 → 组件暴露 `loader` 注入点，生产仍走动态 import（顺带把 400KB 依赖拆出主包） |

另有两处顺序 bug：`view` 被置空后报 `reading 'fit'`（用 `renderSeq` 序号作废旧任务），
以及注入桩时 `root is not defined`（按行号改文件改错了一行，教训：**改代码别用行号偏移**）。

## 5. 遗留与边界

- ~~思维导图仍是自绘列表~~ → **已完成**，改为 markmap 真图（见 §4b）
- **PDF 导出**：前端 `services/pdf.ts` 手写单页 A4（零依赖），但长图主题会超出一页被裁；Word→PDF 不受影响
- **知识服务与引擎双入口**：产品内仍走知识服务（有状态/权限/区块状态），引擎是**无状态纯函数**；
  若后续要把引擎整包发布给同事，建议再拆独立仓库（触发条件：外部调用者 ≥2 个团队）
- **Word 字体**：钉钉原件用 NotoSansCJK，我们钉微软雅黑（Windows 天然有），避免字体缺失导致的回退
- **元信息缺失**：Agent 直接从纯文本起跑时没有 `created_at`/说话人名，封面用「—」占位（不留空、也不写
  「待补充」制造缺料感）；文本里带 `张三 [00:12]` 格式时会自动还原说话人
- **导图节点暂不能点击跳转播放**：markmap 支持节点点击折叠，但与音频时间轴的映射（钉钉能做到）还没接。
  2026-10-19 用户确认**只登记、暂不实现**，已写入 [`progress.md`](../progress.md) 待开始第 12 条，
  含三处改动点（引擎把时间段写进节点 → `SCHEMA` 同步 → 前端绑定 `seekTo()`）与「点击行为会与折叠打架」的注意项
