# EasyShare 启动即用与双击进入

> 日期：2026-07-19  
> 状态：已完成并通过自动化、生产构建和真实 Windows 验收  
> 主题：取消首次使用时的手动“映射到资源管理器”步骤

## 用户问题

- 当前用户双击运行 `easyshare.exe` 后，虽然桌面端会自动启动或复用 Core，但仍要进入“网络驱动器”区域并点击“映射到资源管理器”，才能在 Windows 资源管理器中使用共享空间。
- WPS、百度网盘、天翼云盘等产品给用户的直觉是“启动后即可用”：双击应用完成服务启动，或者在资源管理器中双击已有入口直接进入文件空间。
- EasyShare 当前暴露了 WebDAV、映射等实现细节，用户需要理解“先运行、再映射”两个步骤，不符合文件空间应当开箱即用的预期。

## 目标

- 用户双击启动 EasyShare 后，无需再点击“映射到资源管理器”；桌面端首次初始化时自动启动 WebDAV 并连接配置的网络盘符。
- 映射成功后，用户可以在“此电脑”中像打开普通磁盘一样双击 EasyShare 的盘符进入共享目录。
- 已经存在且确认为 EasyShare 自己的映射时，重复启动桌面端应直接复用，不报“盘符被占用”，也不重复执行有副作用的映射命令。
- 盘符被其他程序占用、WebClient 不可用或认证失败时，桌面界面仍能正常打开，并给出可理解、可重试的错误；不得覆盖或删除不属于 EasyShare 的映射。
- 保留手动“取消映射”和“退出全部服务”能力。用户本次会话中主动取消后，不应被状态轮询立即重新映射；下次重新启动 EasyShare 时再自动连接。

## 用户可见变化与验收标准

### 场景 1：首次双击运行

1. 启动前配置盘符未被占用，也不存在 EasyShare 映射。
2. 用户双击 `easyshare.exe`。
3. EasyShare 自动启动或复用 Core，并仅发起一次自动映射。
4. 无需点击“映射到资源管理器”，配置盘符（当前默认 `Z:`）出现在“此电脑”。
5. 用户双击该盘符可以进入共享根目录，并能正常新建、读取、重命名和删除文件。

### 场景 2：重复启动或已有自身映射

- Core 和 EasyShare 映射都已存在时，再次打开桌面端不弹出占用错误，不破坏现有连接。
- Core 重启但 Windows 中仍保留指向当前 EasyShare WebDAV 地址的映射时，Core 应认领该映射并把状态校准为“已连接”。

### 场景 3：映射失败

- `Z:` 被其他本地磁盘、网络盘或其他程序占用时，EasyShare 不覆盖它。
- 桌面端继续展示附近设备和传输功能，网络盘区域显示未连接，并提供“重新连接”操作。
- 自动映射只在一次桌面初始化中尝试一次；失败后不得随着每秒状态轮询反复执行 `net use`、刷屏日志或重复弹错。
- 错误文案至少说明失败的操作和可行动建议，例如“Z: 已被占用，请释放盘符后重试”；详细系统错误继续写入日志。

### 场景 4：主动取消与退出

- 用户点击“取消映射”后，本次窗口存续期间保持未映射，除非用户主动点击“重新连接”。
- 仅关闭桌面窗口时，Core 和已连接的网络盘保持现有行为，继续运行。
- 点击“退出全部服务”时仍严格执行：取消 EasyShare 映射 → 停止 WebDAV → 停止后台服务 → 退出 Core。

## 非目标

- 本次不实现 Windows Shell Namespace Extension、Cloud Files API 虚拟文件系统、占位文件或按需下载。
- 本次不承诺在“此电脑”中显示与 WPS/百度网盘完全相同的自定义入口、品牌名称、容量信息、右键菜单或图标；仍使用 Windows 标准网络驱动器盘符。
- 本次不实现开机启动、安装器、托盘菜单或登录 Windows 后无界面自动挂载。
- 本次不修改 WebDAV 协议、Digest Authentication、共享根目录或默认端口。
- 本次不增加完整设置页；盘符仍读取现有 `config.json`。
- 本次不在每次启动后强制弹出资源管理器窗口，以免打断只想使用传输功能的用户。

## 设计决策

### 1. 自动连接由桌面初始化触发

桌面前端完成第一次快照读取后：

1. 若 Core 不可用，保持现有连接错误处理，不尝试映射。
2. 若 `driveMapped=true`，初始化完成，不再调用映射 API。
3. 若 `driveMapped=false`，调用现有 `POST /api/drive/map` 一次。
4. 映射 API 继续负责在需要时先启动 WebDAV；成功后刷新快照。
5. 自动尝试失败时把错误留在 UI，等待用户手动重试，不由轮询触发第二次自动尝试。

选择桌面初始化而不是 Core 进程启动的原因：

- 用户提出的入口是“双击运行 EasyShare”，桌面端是明确的用户动作和反馈载体。
- Core 可能在后台被复用；把产品策略放在桌面层，可以避免 Core 崩溃重启时在没有用户界面的情况下不断尝试映射。
- 用户主动取消映射后，Core 的状态轮询不会擅自恢复；只有重新打开桌面端或主动重试才会连接。

### 2. 现有映射必须支持幂等复用

当前 `Mapper.Map` 只要发现目标盘符已有连接就返回 `ErrDriveOccupied`，无法区分“EasyShare 自己的旧映射”和“其他占用”。本次需先查询并规范化远端地址：

- 盘符不存在：执行现有 `net use <盘符> <UNC> ... /persistent:no`。
- 盘符存在，且远端地址等于当前 EasyShare WebDAV 的 UNC/URL：返回成功，Core 将 `DriveMapped` 校准为 `true`。
- 盘符存在，但目标不同或无法证明归 EasyShare 所有：返回占用错误，不覆盖、不删除。

归属判断必须复用取消映射时的同一套地址规范化规则，避免 Map 与 Unmap 对大小写、`/`/`\` 或 WebDAV UNC 格式理解不一致。若无法可靠解析 `net use` 的本地化输出，应将“查询映射信息”收敛成可单元测试的接口，并以保守拒绝为默认行为。

### 3. UI 从“技术开关”改为“连接状态”

网络驱动器卡片调整为用户任务语言：

- 正在自动连接：显示“正在连接到资源管理器…”，连接按钮禁用。
- 已连接：显示“Z: 已连接”，保留“取消映射”；可增加“打开 Z: 盘”快捷按钮，但这不是实现双击进入的前提。
- 未连接且自动尝试失败：主操作显示“重新连接”。
- 不再把“仅启动 WebDAV”作为普通用户的主要操作；如仍为排障需要，可降级为次要/高级操作。

资源管理器中的双击进入由 Windows 标准映射盘行为提供，不为此引入 Shell 扩展。

### 4. 启动状态机

前端需要显式区分以下状态，避免多个异步操作并发：

```text
读取首次快照
  ├─ 已映射 ───────────────→ ready
  ├─ 未映射 → mapping ─成功→ ready
  │                    └失败→ degraded（允许手动重试）
  └─ Core 不可用 ──────────→ error
```

约束：

- 同一窗口初始化最多自动调用一次 `mapDrive`。
- `mapping` 期间手动映射/取消按钮不可重复点击。
- `shutdown` 开始后，自动映射和刷新结果都不得回写状态或再次访问 Core。
- 组件卸载后不得继续显示异步映射结果。

### 5. 保持安全边界

- 自动化只减少点击次数，不降低盘符所有权校验。
- 不记录 WebDAV 密码、API Token 或完整认证命令。
- 非 EasyShare 映射永远不自动断开。
- 自动映射失败不能阻止局域网发现、发送和接收功能继续使用。

## 数据、API 与代码影响

### 配置

- 本次不新增 `config.json` 字段，因此不存在旧配置迁移。
- 继续使用 `DriveLetter`、`WebDAVRoot`、`WebDAVPort` 和现有凭据。
- 如果后续增加“启动时自动连接”开关，应单独设计旧配置迁移和默认值；不要在本次通过缺省布尔字段隐式改变行为。

### Core API

- 不新增 HTTP 路由。
- `POST /api/drive/map` 的契约从“空闲盘符上创建映射”扩展为幂等的“确保该 EasyShare 映射存在”。
- 成功响应仍为 `200 {"mapped": true}`；外部占用仍返回冲突错误。
- `/api/status` 保持字段兼容，但在复用自身旧映射后必须准确返回 `driveMapped=true`。

### 桌面/Wails

- 自动映射可以复用现有 `MapDrive` 绑定，不要求改动自动生成绑定。
- 若实现“打开 Z: 盘”按钮，则新增一个桌面绑定，由 Go 使用经过配置校验的盘符打开资源管理器；增加导出方法后必须通过 Wails 重新生成 `frontend/wailsjs`，不得手工修改生成文件。

### 前端

- `useEasyShare` 增加一次性初始化流程和 `mapping` 状态，取代“挂载完全依赖用户点击”的流程。
- `DrivePanel` 根据连接中、已连接、失败/未连接状态展示对应操作。
- 现有每秒 `refresh` 只读取状态，不负责触发自动映射。

## 兼容与迁移

- 旧桌面端与新 Core 可以共存：新 Core 的 map API 仅变得更幂等，不改变路径和成功响应。
- 新桌面端与旧 Core 基本可共存，但遇到“自身旧映射仍存在、Core 状态丢失”的情况时，旧 Core 仍会报告盘符占用；发布时应继续同时交付配套的两个 EXE。
- 端口、认证方式、盘符格式和 WebDAV 根目录不变。
- Core 异常退出后可能存在外部残留盘符。本迭代只认领远端地址与当前配置完全匹配的映射，不清理无法确认归属的残留项。
- `/persistent:no` 保持不变，不创建永久登录映射。

## 测试计划

### Go 单元测试

- 空闲盘符时执行一次映射命令并成功。
- 目标盘符已经指向当前 EasyShare UNC 时直接成功，不重复映射。
- 目标盘符指向不同 UNC 时返回 `ErrDriveOccupied`。
- 查询输出无法识别时保守失败，不覆盖映射。
- 大小写、斜杠形式和 Windows WebClient UNC 的等价比较正确。
- map API 复用既有自身映射后，状态更新为 `webdav=true`、`driveMapped=true`。
- 原有“映射前自动启动 WebDAV”和有序退出测试继续通过。

### 前端测试

- 首次快照为未映射时，自动调用 `mapDrive` 恰好一次，然后刷新状态。
- 首次快照已经映射时不调用 `mapDrive`。
- 自动映射失败时展示错误，并且后续轮询不会再次调用 `mapDrive`。
- 用户点击“重新连接”可以再次尝试，成功后更新状态。
- `mapping` 期间按钮禁用，避免并发请求。
- 用户主动取消后，轮询不会自动恢复映射。
- 初始化映射与 `ShutdownAll` 并发时，不在 Core 退出后继续轮询或回写过期状态。

### Windows 集成测试

- 在确认空闲的测试盘符上启动 EasyShare，验证无需点击即可出现网络盘。
- 双击网络盘进入目录，验证新建、写入、读取、重命名和删除。
- 关闭桌面窗口后映射和 Core 继续存在；再次启动不报占用。
- 模拟 Core 异常退出但映射残留，再启动后能够安全认领自身映射。
- 用其他网络路径占用测试盘符，启动 EasyShare 后确认原映射未变化且 UI 提示失败。
- 手动取消映射后等待多个轮询周期，确认不会自动恢复；点击“重新连接”后恢复。
- 点击“退出全部服务”，运行 `net use` 并检查无 EasyShare 残留映射或进程。

## 后续产品方向

用户最终需要的是类似 WPS 的网络云盘，而不只是本地 WebDAV 映射：账号/ID、云端容量、上传下载、传输队列、同步文件夹、Windows 原生文件入口，同时保留内网发现、直传与后续局域网加速。该方向需要云端账号与存储、持久化同步引擎及 Windows CfAPI/Sync Root，已独立记录在 [`../product-vision.md`](../product-vision.md)，不在本次自动映射迭代中混入未验证的 Shell 扩展。
