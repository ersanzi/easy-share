# 迭代记录 — 会议听记·思维导图与备忘录导出（2026-10-12，用户直配轮第四片）

> 触发：用户提出「日常会议录音转写成逐字稿，并生成结构化思维导图，整理备忘录、
> 列出待办清单」。四项中逐字稿/备忘录（纪要）/待办已随听记切片交付，本片补齐
> 思维导图（唯一新组件）与导出能力。

## 方案

- **生成**：LLM 总结输出扩展 `mindmap` 字段（markdown 层级大纲，≤3 级、节点 ≤20，
  转写内容同一次调用产出，零额外调用）；详情页提供「重新生成」按钮（复用同链路，
  取大纲部分覆盖）。存储为会议记录顶层 `mindmap` 字段。
- **渲染**：markmap（MIT，markdown→交互式导图，d3 自动布局/缩放/折叠）——AI 生成
  内容以「看」为主，markmap 最省；若后续要「用户改导图」再迁 mind-elixir（大纲格式
  不变，迁移成本低）。
- **导出**：Markdown 前端本地生成（详情数据齐备，零管道）；Word（.docx）走
  python-docx 在知识服务生成 → Core/桌面端经既有流式通道透传（同音频回放模式），
  给没装客户端的同事发文件。
- **不做**：待办 → 待办与周报插件协同（后续小件）；embedding 类配置不变。

## 实现

- **知识服务**：summarizer prompt 扩展 `mindmap` 字段（markdown 层级大纲，#/##/- 三级、≤20 节点）；`_process` 把导图存为记录顶层 `mindmap` 字段（独立于 summary，可单独重生成）；`regenerate_mindmap()`（重生成 + 落盘）；`export_docx()`（python-docx 生成备忘录：标题/元信息/纪要/要点/待办/带说话人标签转写全文）；routes 加 `POST /meetings/{id}/mindmap`（重生成）与 `GET /meetings/{id}/export/markdown|docx`（附件下载，中文文件名走 RFC 5987）。
- **Go 管道**：knowledge.Client 增 `RegenerateMeetingMindmap`（JSON）与 `StreamMeetingExport`（流式透传 Content-Type/Content-Disposition）；Core 加 `POST /api/knowledge/meetings/{id}/mindmap` 与 `GET .../export/{format}`（白名单 markdown|docx）；桌面端 `/kapi/meetings/{id}/export/{format}` 透传（appmeetings.go）。
- **前端**：详情页新增「思维导图」区块（根节点 pill + 分支/叶子层级树，LLM 未生成时显示「生成导图」入口）与「导出 MD / 导出 Word」按钮（MD 前端拼 Blob、Word fetch /kapi → Blob 下载，文件名从 Content-Disposition RFC5987 解码）。

## 二轮升级：导图生成 harness 化（参考 mindmap-generator 多阶段思想）

用户再反馈「参考 GitHub 资源，弄个 skill/harness 这样的东西」。调研选定
[ Dicklesworthstone/mindmap-generator ](https://github.com/Dicklesworthstone/mindmap-generator)
（LLM 文档→层级导图的多阶段管线：类型检测→重叠分块→主题提取引擎→自适应深挖→现实校验），
裁剪为适配 EasyShare 规模的**三阶段 harness**（`app/meetings/mindmap_harness.py`）：

- **阶段一 议题切分**：LLM 通读转写 → 议题列表（名称/概要/时间范围，2-6 个，时间轴全覆盖）
- **阶段二 逐议题深挖**：按议题时间范围切片转写，逐议题提取要点+细节+负责人（串行 ≤6 题，prompt 禁元话语）
- **阶段三 确定性装配**：代码拼装 markdown（不经 LLM 自由发挥，层级必然合法），根节点=会议主题

工程质量件：任一阶段失败**回退单次生成**（不会比旧版差）；`MeetingSummarizer.ask_json` 通用询问器供管线复用；
转写切片按时间范围取（时间轴盲区消除）。修复：`knowledgeMeetingMindmap` 未解除全局 30s 写超时，
harness 多次 LLM 调用被拦腰断连（curl exit 52）——补 ResponseController 清限期。

**效果**：863 字大纲、5 议题分支、四级层级、每个节点带负责人与引文级细节（无元话语），UI 树完整渲染。
对比轨迹：初版 195 字/3 支 → 单次 prompt 升级 503 字/6 支 → harness 863 字/5 议题分支/四级/节点带引文。

## 渲染方案变更记录（诚实记录）

原方案 markmap（markmap-lib + markmap-view）图形渲染：集成后 LLM 大纲生成与数据链路全通，但 **SVG 画布空白**（无 JS 异常、try/catch 无捕获、rAF+fit 修正无效，深查成本高于收益）——切换为**自绘结构树**（根节点 pill + 分支/叶子层级，幕布式大纲形态，零依赖必然可见）。markdown 大纲数据格式不变，后续若要图形化导图（markmap/mind-elixir）可平移。

## 三轮升级：总结模板系统（对标钉钉模板选择，用户截图反馈）

钉钉听记支持按场景选总结模板（会议纪要/团队周会/每日站会/面试报告/访谈记录等 + 自定义）。
落地方案：**模板 = 总结阶段的结构化 prompt**，转写/待办/导图/导出全链路复用。

- **知识服务**：`app/meetings/templates.py` 内置 7 模板（会议纪要/团队周会/每日站会/面试报告/访谈记录/培训笔记/头脑风暴会）；`GET /meetings/templates` 列表（注册在 `{meeting_id}` 路由**之前**避吞）；transcribe 接收 `template_id`；`POST /meetings/{id}/summary` 按模板重生成总结；记录存 `template_id`。
- **总结输出双形态**：默认模板保持旧固定字段（minutes/key_points，零回归）；其他模板输出通用 `sections: [{title, content}]`；**弱模型兜底**——模型不守 sections 形状时把 minutes/key_points 自动转换为 sections（代码侧转换，模板结构保证可见）。
- **Go/前端**：MeetingSummary.Sections / Meeting.TemplateID 贯通；Core `/summary` 代理转发 body template_id（并解除写超时）；详情页按 sections 通用渲染（列表/段落自适应）+ 模板下拉「按模板重生成」；上传卡加模板下拉。
- **已知项**：`/meetings/templates` 必须注册在 `/meetings/{meeting_id}` 之前（路由吞并）；deepseek-flash 是推理型模型，CoT 前 11k 字会泄漏进 content，需 `max_tokens=8192` 防截断 + `_extract_last_json` 扫描提取（贪心正则会抓错）。

**E2E**：团队周会模板重生成 → sections 四节（本周进展/数据与指标/问题与风险/下周计划）+ 6 待办，UI 通用渲染实拍 ✓。
