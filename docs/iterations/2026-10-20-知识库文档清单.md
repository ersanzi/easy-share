# 2026-10-20 · 知识库文档清单（问答 / 文档）

## 用户问题

阅读页做好后，知识库仍然只有一个问答框：

- 用户不知道知识库里到底有哪些文档、哪些正在处理、哪些入库失败；
- 无法从列表进入阅读页，只能先提问、再从引用里碰运气；
- 面板上的“多少份文档”实际用的是索引块数（`/health.records`），数字本身是错的；
- 网盘还没有“加入知识库”入口，当前入库仍靠服务器共享目录；先把已入库文档变成可见、可读、状态可解释的清单，后面接网盘入库才有落点。

## 目标

- 知识页增加“问答 / 文档”切换，默认问答，原对话与引用行为不变；
- 文档页列出已入库文档：文件名、块数、处理时间、归属、最新状态；
- 最新任务失败但存在上一版时，明确显示“更新失败，当前可读上一版”，并允许打开上一版；
- 处理中/排队中自动轮询，处理完自动刷新；
- 从列表点一行直接打开上一片做的只读阅读页；
- 修正“份文档”计数：`/health` 增加真实文档数。

## 非目标

- 网盘“加入知识库”（下一片：涉及控制面对象键、归属与 SSO，不能只靠前端拼）；
- 失败重试按钮（`/jobs/{id}/retry` 目前没有按文档可见性校验，直接暴露给列表会开越权口子；先不做，等补权限后一起）；
- 分页、全文检索、排序切换（当前最近 200 份 + 文件名过滤）；
- 编辑、协同、上传/删除知识库文档。

## 设计决策

1. **清单按 `file_id` 聚合任务历史，而不是只列任务。**
   `knowledge/app/jobs/store.py` · `list_documents` 用子查询选出最近更新的 `file_id`，再取这些文档的全部任务；路由取“最近一次任务”（`latest`）与“最近一次成功任务”（`last_completed`）。两者分开是核心：覆盖上传失败时，旧索引仍然可读，不能把文档误报成不可用。

2. **`ready` 与 `status` 分开。**
   `status` 是最新任务状态（可能 `failed`），`ready` 表示是否存在成功版本，`read_version_id` 指向可读的那一版。前端用“更新失败”而不是“入库失败”表达“最新失败但旧版可读”。

3. **可见性沿用同一判据。**
   `knowledge/app/api/routes.py` · `list_documents` 对每个文档用 `knowledge/app/rag/permissions.py` · `can_view_document` 检查最新任务的 owner/visible_depts；admin 全见，未登录（本地 lab/auth 关闭）保持历史行为。清单不返回任何不可见的文件名或错误。

4. **修正文档计数。**
   `/health` 新增 `documents = len(vector_store.doc_owners())`；`records` 仍是索引块数。前端“份文档”改用 `documents`，`records` 只作为悬停提示。此前把块数当文档数是口径错误，不是显示偏好。

5. **前端抽独立列表组件。**
   `frontend/src/components/KnowledgeDocumentList.vue` 负责渲染、状态标签、空态与搜索输入；`KnowledgePanel.vue` 只负责取数、轮询和打开阅读页。列表可单测，面板不再继续膨胀。

6. **轮询边界。**
   只有切到“文档”且存在 `queued/processing` 任务时每 3 秒静默刷新；切回问答、退出登录、组件卸载都会清定时器。静默刷新失败不弹错，避免每 3 秒一个红条。

## 兼容与迁移

- 新增知识服务 `GET /documents` 与 Core `GET /api/knowledge/documents`；Wails 新增 `KnowledgeDocuments`。
- `/health` 新增 `documents` 字段（加法，旧客户端忽略）。
- 无 DDL、无配置新增、无端口变化；`/query`、阅读页、产物端点行为不变。
- 旧 Core + 新桌面端：新方法不存在，前端只在知识页使用，构建时绑定已同步；新 Core + 旧桌面端无影响。

## 发布与回滚

- 本轮只改源码与测试，**未构建安装包、未重启本地程序、未动活栈**。
- 回滚：移除 `/documents` 路由与清单页即可；`/health.documents` 是加法，可保留。
- 真机验收清单（录音结束后）：
  1. 知识页出现“问答 / 文档”，默认问答，原对话正常；
  2. 文档页显示已入库文档、块数、时间、状态；点一行打开阅读页；
  3. 处理中任务 3 秒内自动刷新到完成；
  4. 制造一次覆盖失败（如删掉源对象后重新入库）→ 状态显示“更新失败”，仍能打开上一版；
  5. 普通账号看不到别人的私有文档；
  6. 会话条“份文档”与实际清单数量一致。
