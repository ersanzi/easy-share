## 轴① RAG 检索质量（本轮主题：评测方法学，服务收件箱 P2「上下文敏感性难例」）

1. **Chunking 策略是域依赖的，必须固定评测集实证**（P2 参考；可落地=是，方法引用）。2026 年多篇评测收敛到同一结论：法律文档固定块吃亏、散文语义块占优、代码 late-interaction 占优（[arXiv 2607.01852](https://arxiv.org/html/2607.01852v1)、[Chroma Research](https://www.trychroma.com/research/evaluating-chunking)、[Future AGI 2026](https://futureagi.com/blog/evaluating-rag-chunking-strategies-2026/)）。印证项目「42 条评测集 + eval 脚本」路线正确，无现成银弹可抄。
2. **合成测试集 + hard negatives 是难例扩充的主流方法**（P2 参考；可落地=是）。[NVIDIA 开发者博客](https://developer.nvidia.com/blog/evaluating-and-enhancing-rag-pipeline-performance-using-synthetic-data/)讲 hard negatives 在对比学习与 RAG 评测中的作用；[Ragas testset generation](https://docs.ragas.io/en/v0.1.21/concepts/testset_generation.html) 提供问题类型多样性清单；[Red Hat 2026-02](https://developers.redhat.com/articles/2026/02/23/synthetic-data-rag-evaluation-why-your-rag-system-needs-better-testing) 讲从自有知识库生成带 ground-truth context 的评测集。直接服务收件箱 P2 难例扩充任务：构造「上下文敏感性」难例时可借 hard-negative 思路（同文档近似块作干扰项），并用 Ragas 的类型清单自查覆盖面。
3. **合成基准有效性有边界**（P3 提醒）。[arXiv 2508.11758](https://arxiv.org/html/2508.11758v1)：合成分布 ≠ 真实分布，需满足实验条件才可用。联动项目现状：难例扩充落地后，仍要用观察期真实 QueryLog 的盲区查询校准（周报脚本产出即输入）。
