# 2026-10-17 WPS 云盘前端布局对标

> 用户口径：「学习下钉钉的钉钉文档和 wps 云盘，特别是学习下 wps 的**前端布局**」
> 方法：**直接启动本机 WPS 云盘客户端观察真实界面**（不是逆向字符串）——
> 布局是视觉产物，观察实际运行的产品远比读二进制准确。
> 环境：`D:\Program\office\WPS Office\12.1.0.29161\office6\wpscloudlaunch.exe`，
> 企业空间形态（山东绿霸化工股份有限公司，高级版）

## 0. 一句话结论

WPS 云盘的布局**不是「文件列表 + 侧边栏」的朴素组合**，而是一个**三层信息架构 + 三处常驻上下文**：
左侧「内容源」、顶部「身份与搜索」、主区「视图与筛选」，
再叠上**底部的用量常驻条**与**悬停浮出的行内操作条**。
我们现在的网盘页只实现了「主区列表 + 一个页面级搜索」，缺的是：内容源分类、视图级筛选、行内操作、用量常驻。

### ① 身份栏 + 全局搜索

| 元素 | 设计要点 | 为什么 |
| --- | --- | --- |
| 组织名 + 「高级版」徽章 | 常驻左侧 | 多租户产品第一等上下文：**我此刻在哪个组织里**。切组织是所有操作的前提 |
| 全局搜索占位符 | 「搜索文件、**模板、文库、应用、技巧**」 | 占位符直接**枚举可搜域**——用户不必先知道搜索范围 |
| 搜索框位置 | 居中，最大宽度约 40% | 视觉重心；不是塞在角落的图标 |

### ② 主区标题行

```
我的云文档  ⟳                    [新建] [导入] │ 智能问答
```

- **标题带刷新按钮**（⟳ 紧跟标题，不是孤立图标）
- **主操作在右**（新建/导入），与左侧栏的「+ 新建」是同一动作的**两个入口**——
  一个在内容源区（全局），一个在视图区（当前目录）
- **AI 入口**（智能问答）用竖线分隔，视觉上是「附加能力」不是主操作

### ③ 视图筛选行（**我们完全没有的一层**）

```
全部类型 ▾                          最后修改 ↓   大小 ▾      [☰] [ⓘ]
```

| 元素 | 语义 |
| --- | --- |
| **全部类型 ▾** | 按类型筛选（文档/表格/演示/PDF/图片…），**与搜索互补**：搜索按名，筛选按类 |
| **最后修改 ↓ / 大小 ▾** | 排序键**并列显示**为列头，带方向箭头，可点击切换——不是下拉菜单元件 |
| 右侧 ☰ | 列表密度/视图切换 |
| 右侧 ⓘ | 该视图的说明 |

> **关键洞察**：排序不是「工具栏里的 select」，而是**列头本身**。
> 用户视线在文件列表上，操作就在视线上——不必把眼睛移到工具栏再移回来。

### ④ 文件行

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 图标 | 按文件类型着色（蓝文件夹/绿表格/紫文档/红 PDF） | **颜色即类型**，扫视时不读文字 |
| 名称 | 主信息，左对齐 | 文件夹无大小列（对象存储里目录没有 size，与我们的模型一致） |
| 最后修改 | 相对右对齐 | 统一格式 `2026/5/7` |
| 大小 | 最右 | 人类可读（`12.8KB`），文件夹留空 |

### ⑤ 悬停行内操作条 ★**最值得抄的一处**

未悬停时行是**干净的**（只有图标+名称+时间+大小）。
鼠标悬停时整行高亮为浅灰底，并**在行内浮现**：

```
[✓复选框] [图标] check list.pdf [☆星标] [+ 标签]        [分享] [⋯更多]
```

- **复选框**：悬停才出现 → 批量操作入口，但平时不占视觉
- **星标 ☆**：常驻在名称后（收起态也可见，因为它是个**状态**不是动作）
- **+ 标签**：行内直接加标签，不必打开属性面板
- **分享**：主操作（蓝色实心按钮），放最右
- **⋯**：其余动作收进菜单

设计原则：**动作跟着对象走**。用户已经用眼睛选中了那一行，操作就该出现在那一行，
而不是让他再回到顶部工具栏去找。

### ⑥ 列表终止标记

「没有更多了」——**明确告诉用户列表结束了**，而不是让用户怀疑「是不是还有没加载的」。
比无限滚动时的静默到底要好。

### ⑦ 智能助手浮球

右下角常驻圆形按钮，不占布局空间。任何页面都能唤起。

### ⑧ 用量常驻条 ★

```
企业空间  86.87G / 3.92T
▓▓░░░░░░░░░░░░░░░░░░░░
了解更多企业云服务 >
```

- **常驻在侧栏底部**，不占用主区
- 数值 + 进度条 + 引导链接三件套
- 对比：我们只在「设置页账号卡片」和「此电脑磁贴副标题」里显示用量，
  网盘页本身**看不到我还剩多少空间**——而这是用户最常问的问题之一

### ⑨ 左侧栏的三段式分组

```
[新建][打开]          ← 动作区（常驻顶部，最大视觉权重）
最近 / 星标 / 共享      ← 快捷视图（无分组标题，靠留白区隔）
云文档                 ← 分组标题
  我的云文档 / 团队文档 / 知识库 / 我的设备 / 标签 / 回收站
本地                   ← 分组标题
  桌面 / 文档 / 下载 / 微信文件 / 浏览
常用                   ← 分组标题
  工作台
[用量条]              ← 常驻底部
```

- 分组**有标题**（云文档 / 本地 / 常用），组内缩进
- 可展开项用 `▸/▾` 箭头（团队文档、我的设备、标签）
- **回收站放在「云文档」组的最末**——它是内容源之一，不是独立页面

### ⑩ 最左侧图标轨道

6 个图标竖排（云盘/团队协作/通讯录等），是 **WPS365 大一统入口**。
这是平台级设计，我们单产品不需要照抄（见 §4 明确不抄）。

## 2. 与我们当前网盘页的差距

| 维度 | WPS | 我们现在 | 差距性质 |
| --- | --- | --- | --- |
| 内容源 | 左侧栏 3 组 12 项（我的/团队/知识库/设备/标签/回收站/本地…） | 无左栏，只有页面顶部几个文字按钮 | **结构性缺失** |
| 类型筛选 | 「全部类型 ▾」独立一层 | 无 | 缺失 |
| 排序 | 列头直点（最后修改↓ / 大小▾） | 工具栏 select + ↑↓ 按钮 | **形态落后** |
| 行内操作 | 悬停浮现（复选框/星标/标签/分享/更多） | 每行右侧固定「打开」按钮 | 缺失 |
| 列表终止 | 「没有更多了」 | 无 | 缺失 |
| 用量 | 侧栏底部常驻进度条 | 只在设置页 | **位置错误** |
| 回收站 | 侧栏内容源之一 | 顶部文字按钮 → 覆盖层 | 入口层级不符 |
| 搜索 | 顶部全局 + 可搜域枚举 | 主区搜索框（当前目录） | 范围小于业务需要 |
| AI 入口 | 标题行竖线分隔 + 右下浮球 | 无 | 无此需求 |

## 4. 明确不照抄

| 不抄 | 理由 |
| --- | --- |
| 最左侧 6 图标轨道 | WPS365 平台级入口（云盘只是其一），我们单产品无对应物 |
| 「知识库 / 我的设备 / 标签」三项 | 知识库我们有独立一级导航（`知识`页）；设备管理是局域网能力不是云盘内容源；标签是 P2 之后的事 |
| 本地「桌面/文档/下载/微信文件」 | 这是 WPS 的本机文件聚合，与我们的「局域网收件箱」定位不同 |
| 「新建 Word/Excel/PPT」 | WPS 是文档套件，我们是传输/存储工具；我们没有文档编辑器 |
| 智能问答 / 智能助手浮球 | 我们有独立「知识」页做问答，不塞进网盘页 |
| 企业版徽章/了解更多企业云服务 | 商业形态差异 |
