# EasyShare 客户端统一文件工作台设计

> 状态：产品与架构方向已确认，等待按阶段实施  
> 日期：2026-07-26  
> 适用范围：EasyShare Windows/macOS 桌面客户端、Go Core、本机系统文件入口，以及后续知识能力入口  
> 相关文档：[产品方向](product-vision.md) · [当前架构](architecture.md) · [Cloudreve 对标](cloudreve-benchmark.md) · [知识平台](knowledge-platform.md) · [进度与路线](progress.md)

## 1. 文档目的

本文把 EasyShare 客户端从当前能力型界面演进为成熟文件产品的方向固定下来，作为后续客户端迭代的信息架构、交互模型、领域契约和技术边界基线。

本文参考 WPS 云盘等成熟文件客户端，但不以复制功能数量为目标。EasyShare 的目标是把云盘、局域网直传、同步和知识处理组织成一套一致的文件体验：

> 用户只表达“这个文件要做什么、去哪里”，客户端与 Core 决定使用局域网、云端、缓存、同步或知识管线完成操作。

本文是目标设计，不代表所有能力已经实现。当前可用能力仍以 [architecture.md](architecture.md) 和 [progress.md](progress.md) 为准。

## 2. 背景与现状判断

截至 2026-07-26，客户端已经具备以下良好基础：

- Wails + Vue 单窗口桌面界面；
- 独立 Go Core 进程承担局域网发现、传输、WebDAV 和云盘能力；
- Core 事件流实时推送，前端以定时快照作为断线兜底；
- Windows 托盘和“此电脑”Shell NameSpace 入口；
- 云盘上传、下载、删除、分享和基础预览；
- 全窗口拖放，并根据当前页面路由到网盘上传或附近设备发送；
- macOS Finder/WebDAV 与菜单栏方向已经建立平台抽象。

当前客户端信息架构主要是：

```text
概览
附近设备
传输任务
网盘
设置
```

它适合 MVP 阶段展示能力，但随着同步、文件版本、知识处理和跨设备能力加入，会出现三个问题：

1. 用户需要先理解“应该进入哪个技术模块”，再完成文件操作；
2. 局域网传输、云上传下载、同步和文档处理容易形成互不相通的任务状态；
3. 云盘文件仍偏向对象存储 `key` 视角，难以稳定承载重命名、版本、回收站、同步状态和知识索引。

因此下一阶段不应先堆叠更多页面，而应先建立统一的产品模型和客户端契约。

## 3. 产品定位

### 3.1 一句话定位

```text
EasyShare = 统一文件入口 + 云盘 + 附近设备 + 同步 + 知识能力
```

EasyShare 不做缩小版 WPS Office，也不承担完整文档编辑器、模板市场和办公门户。它重点解决：

- 文件从本机快速进入云端、其他设备或知识库；
- 同一文件在多个入口中保持一致身份、版本和状态；
- 同一局域网时自动优先直传，不在局域网时使用云端中转；
- 应用关闭、断网或重启后任务仍可理解、可恢复；
- Windows Explorer/macOS Finder 成为日常文件入口；
- 文件内容在授权范围内可被搜索、问答并准确引用。

### 3.2 三个核心产品对象

客户端应围绕三个对象组织，而不是围绕底层协议组织。

#### 文件 File

用户真正关心的对象。文件具有稳定身份、当前版本、所在目录、可用位置、同步状态和可执行能力。

#### 目的地 Destination

文件可以被送往：

- 云盘目录；
- 附近可信设备；
- 同步文件夹；
- 知识库；
- 本机下载目录；
- 分享对象。

#### 活动 Activity

所有需要时间、可能失败或需要恢复的操作统一成为活动任务：

- 局域网发送/接收；
- 云上传/下载；
- 同步上传/下载；
- 文档解析、OCR、切块和索引；
- 后续的解压、批量移动、批量删除和版本恢复。

## 4. 设计原则

### 4.1 用户表达意图，系统选择技术路径

界面使用“发送给设备”“保存到云盘”“加入知识库”等语言，不暴露 IP、端口、WebDAV、S3、Embedding、queryMode 等技术参数。

### 4.2 一处发起，处处可见

任务可以从首页、文件页、附近设备、Explorer/Finder 或托盘发起，但都进入同一个任务中心，并使用相同状态和错误模型。

### 4.3 Core 持有可靠状态，UI 只展示与发出命令

Vue 不拥有长任务真相，不直接访问 RustFS、Python 服务或业务数据库。UI 关闭不等于任务终止；重新打开后必须能从 Core 恢复状态。

### 4.4 文件身份与路径分离

路径、文件名和对象存储 key 都会变化，不能作为长期业务身份。分享、版本、同步、知识索引和任务应关联稳定 `fileId + versionId`。

### 4.5 能力由后端声明，前端不猜测

能否预览、分享、同步、恢复、加入知识库，应由 Core/控制面返回 capabilities。前端不通过扩展名或页面位置自行推断权限和能力。

### 4.6 离线与失败是一等状态

客户端必须明确区分：

- 等待网络；
- 等待设备上线；
- 等待用户确认；
- 可重试失败；
- 不可重试失败；
- 冲突；
- 权限不足；
- 空间不足。

不能把所有情况统一显示为“操作失败”。

### 4.7 系统文件入口保持轻量

Explorer/Finder 扩展负责入口、状态和命令桥接，不直接访问云端、运行完整同步引擎或写业务数据库。

## 5. 对 WPS 的借鉴边界

### 5.1 应借鉴

| 能力 | 借鉴原因 | EasyShare 落地方式 |
| --- | --- | --- |
| 稳定左侧导航 | 降低不同页面之间的认知成本 | 首页、文件、任务、同步、设备、知识、设置 |
| 顶部全局搜索 | 文件入口不应受当前页面限制 | 文件名搜索先行，逐步增加内容搜索和问答 |
| 最近文件 | 用户打开客户端通常是继续工作 | 首页展示最近打开、上传、下载和处理文件 |
| 全局上传入口 | 上传不应要求先进入云盘目录 | 顶栏“上传”按钮 + 全局拖放 |
| 统一任务面板 | 长任务需要随时可见、可控制 | 全局活动抽屉 + 独立任务中心页面 |
| 账户与容量常驻 | 让用户预判是否可上传、是否登录 | 侧栏底部或顶栏展示摘要，不做大面积营销卡片 |
| Explorer/Finder 集成 | 用户日常工作主要发生在文件管理器 | 近期 WebDAV/NameSpace，后续 CfAPI/FileProvider |
| 文件状态图标 | 云端、本地和冲突状态需要直观表达 | 仅云端、可离线、同步中、冲突、错误 |

### 5.2 不应照搬

- 不复制复杂办公门户、模板市场和营销卡片；
- 不在首页堆叠所有 AI 功能；
- 不内置完整 Office 编辑器；
- 不让“网盘、协作、知识、设备”各自建立一套文件和任务模型；
- 不把技术配置交给普通用户；
- 不为了视觉相似而牺牲文件列表密度、键盘操作或可访问性；
- 不在文件模型、任务恢复和权限边界未完成时提前开发复杂 WPS 插件。

## 6. 目标信息架构

```text
首页
文件
任务中心
同步文件夹
附近设备
知识
设置
```

建议从现有页面渐进迁移：

| 当前入口 | 目标入口 | 迁移方式 |
| --- | --- | --- |
| 概览 | 首页 | 保留服务状态，增加最近文件、活动摘要和全局动作 |
| 网盘 | 文件 | 从平铺对象列表升级为目录、搜索、状态和预览工作区 |
| 传输任务 | 任务中心 | 从局域网任务扩展为所有 Activity |
| 附近设备 | 附近设备 | 增加信任、配对和传输路径说明 |
| 设置 | 设置 | 按账户、设备、同步、网络、安全、缓存和诊断分组 |
| 无 | 同步文件夹 | 同步引擎 MVP 就绪后出现，不提前提供空入口 |
| 无 | 知识 | 生产级权限和任务接入后出现，不直接嵌入 `/lab` |

未实现的页面不应以不可用菜单占位。只有具备最小闭环时才进入主导航。

## 7. 首页工作台

### 7.1 布局草图

```text
┌────────────────────────────────────────────────────┐
│ 搜索文件、内容或问答           ＋上传   活动(2)  头像 │
├──────────┬─────────────────────────────────────────┤
│ 首页      │  拖入文件，选择它要去哪里               │
│ 文件      │                                         │
│ 任务中心  │  [发送到设备] [保存到云盘]              │
│ 同步      │  [加入同步]   [加入知识库]              │
│ 设备      ├─────────────────────────────────────────┤
│ 知识      │  最近使用                               │
│           │  员工手册.docx   产品方案.pdf           │
│ 设置      ├─────────────────────────────────────────┤
│           │  正在进行                               │
│ 空间 62%  │  上传产品方案.pdf     62%               │
│ 设备正常  │  员工手册解析中       第 4/8 阶段        │
└──────────┴─────────────────────────────────────────┘
```

### 7.2 首页必须提供

- 全局搜索入口；
- 主上传按钮；
- 全局拖放区域；
- 最近使用文件；
- 进行中与失败任务摘要；
- 云端空间、网络和设备状态摘要；
- “继续上次操作”或最近访问目录；
- 对失败任务的明确修复入口。

### 7.3 首页不提供

- 广告和营销轮播；
- 大量只读统计卡片；
- 技术服务启停开关作为视觉中心；
- 未接入生产权限的知识实验台；
- 重复显示所有二级页面的完整内容。

## 8. 全局拖放与智能路由

### 8.1 拖放规则

| 放置位置 | 默认意图 |
| --- | --- |
| 文件/云盘目录 | 上传到当前目录 |
| 某台附近设备 | 发送给该设备 |
| 同步文件夹 | 复制或移动到该同步目录 |
| 知识库 | 上传并发起解析/索引 |
| 首页通用区域 | 显示目的地选择器 |
| 其他无明确目的地页面 | 显示目的地选择器，不静默猜测 |

目标选择器使用用户语言：

```text
你想如何处理这些文件？

○ 保存到云盘
○ 发送给附近设备
○ 加入同步文件夹
○ 加入知识库
```

系统可以记住最近选择，但涉及覆盖、删除、公开分享等高风险操作时不得静默执行。

### 8.2 智能传输路径

当用户选择“发送给某设备”时，Core 根据策略决定路径：

```text
同一局域网 + 已信任 + 对端在线
    → 局域网直传

不在同一局域网或直传失败，且允许云端回退
    → 上传云端并通知目标设备

目标设备离线
    → 云端暂存或等待设备上线

本机离线
    → 本地排队，网络恢复后继续
```

客户端只显示对用户有价值的解释：

- “正在通过局域网发送”；
- “目标设备不在当前网络，已切换为云端传输”；
- “当前离线，联网后自动继续”；
- “等待目标设备上线”。

不得暴露端口、对象 key 或内部路由参数。

## 9. 统一任务中心

### 9.1 任务类型

第一阶段至少统一：

```text
lan_send
lan_receive
cloud_upload
cloud_download
```

后续扩展：

```text
sync_upload
sync_download
parse
ocr
index
archive
restore_version
batch_operation
```

### 9.2 状态模型

推荐统一状态：

```text
queued             排队中
running            进行中
paused             已暂停
waiting_network    等待网络
waiting_device     等待设备
waiting_user       等待用户确认
completed          已完成
failed             失败
cancelled          已取消
```

局域网接收的 `pending/accepted/rejected` 可以在兼容期保留，但 UI 最终应映射到统一用户语义。

### 9.3 任务能力

任务中心按任务状态返回可执行能力，而不是由 Vue 自行判断：

```text
canPause
canResume
canRetry
canCancel
canOpen
canOpenFolder
canShowDetails
```

### 9.4 任务展示

任务中心同时提供：

- 顶栏活动按钮：显示正在进行和失败数量；
- 全局活动抽屉：在任何页面快速查看与控制；
- 独立任务页面：支持筛选、历史记录和错误详情；
- 托盘摘要：后台运行时展示活动任务和最近完成；
- 系统通知：完成、需要确认或不可恢复失败时通知。

任务列表默认按“进行中 → 需要处理 → 最近完成”排列，并支持按操作批次分组。

### 9.5 可靠性约束

- 任务由 Core 持久化，UI 不作为状态真相源；
- 创建动作携带稳定 `operationId`，重试请求不得重复创建同一业务操作；
- Core 重启后恢复可恢复任务，或明确标为需要用户处理；
- 进度事件可以节流，但终态事件不可丢失；
- WebSocket 断线后，UI 通过快照重新校准；
- 失败必须包含稳定错误码、可读说明和是否可重试；
- 清除历史只删除终态展示记录，不得取消正在运行的任务。

## 10. 文件工作区

### 10.1 目标布局

文件页面采用成熟文件管理器结构：

- 左侧：目录、最近、收藏、分享、回收站；
- 中间：列表/网格视图、面包屑、排序、筛选和多选；
- 右侧：预览、版本、状态和常用动作；
- 顶部：上传、新建文件夹、搜索和任务入口。

### 10.2 文件状态

列表行需要显示但不过度干扰：

```text
仅云端
本机可用
始终保留
同步中
等待上传
冲突
错误
解析中
可检索
```

颜色不能成为唯一提示；图标必须配合文本、tooltip 或无障碍标签。

### 10.3 文件动作

统一动作集合：

```text
打开
预览
下载
发送到设备
分享
收藏
重命名
移动
删除
查看版本
始终保留在此设备
释放本地空间
加入知识库
```

UI 根据 capabilities 只显示或禁用可用动作，并在禁用时说明原因。

### 10.4 大目录性能

文件目录进入服务端控制面后必须支持：

- 游标分页或增量列表；
- 列表虚拟化；
- 缩略图懒加载与本地缓存；
- 搜索防抖和请求取消；
- 文件事件增量更新，避免每次全量刷新；
- 切换目录时保留滚动位置与选择状态。

## 11. 同步文件夹体验

同步模式使用普通用户能理解的名称：

### 11.1 备份到云端

```text
本地目录 → 云端目录
```

本地变化上传到云端，云端变化不自动覆盖本地。适合照片和资料备份。

### 11.2 双向同步

```text
本地目录 ↔ 云端目录
```

本地与云端互相传播创建、修改、移动和删除。发生无法自动合并的变化时进入冲突中心，不得静默覆盖。

### 11.3 按需文件

文件默认仅保留占位，需要时下载，可由用户切换：

- 始终保留在此设备；
- 释放本地空间；
- 当前正在下载；
- 当前不可离线使用。

按需文件依赖 CfAPI/FileProvider，不应在 WebDAV 阶段伪装成已经具备。

### 11.4 冲突处理

```text
员工手册.docx 存在两个版本

本机：2026-07-26 12:30
云端：2026-07-26 12:35

[保留本机] [保留云端] [保留两个版本] [打开比较]
```

默认安全策略是保留两个版本；只有具备明确版本前提时才允许覆盖。

## 12. 知识能力的客户端形态

### 12.1 文件能力，而不是技术实验台

生产客户端不直接嵌入或调用 `/lab`。用户看到的是文件处理状态：

```text
未加入知识库
正在解析
正在识别扫描内容
正在建立索引
可搜索和问答
处理失败
```

文件动作提供：

```text
加入知识库
重新处理
搜索文件内容
向知识助手提问
查看引用位置
```

### 12.2 引用与版本

知识回答必须展示：

- 来源文件；
- `fileId + versionId`；
- 页码、章节、表格、工作表/行或幻灯片位置；
- 可点击的原文预览入口。

文件产生新版本后，旧版本索引不能被当作当前版本回答；索引切换必须在新版本构建成功后原子生效。

### 12.3 与 WPS 插件的关系

WPS 插件是后续独立交付入口，不复制桌面客户端业务逻辑。它通过同一控制面和知识 API 完成：

- 登录与授权；
- 搜索企业知识；
- 根据当前文档上下文提问；
- 插入带来源的内容；
- 把当前文档登记或上传到 EasyShare。

插件不得直接访问 RustFS 凭据、Core 内部数据库或无授权的本机知识接口。

## 13. 客户端技术架构

### 13.1 保持现有技术栈

当前阶段不建议切换 Electron、Flutter、Tauri 或前端框架。继续使用：

```text
Vue 3 + TypeScript
        ↓
Wails bindings / 本机版本化 API
        ↓
Go Desktop
        ↓
easyshare-core
```

技术栈本身不是当前主要瓶颈。优先解决领域模型、任务可靠性、文件身份和系统集成边界。

### 13.2 目标分层

```text
Vue UI
  ├─ App Shell / Navigation
  ├─ Home Workbench
  ├─ File Workspace
  ├─ Activity Center
  ├─ Device / Sync / Knowledge Views
  └─ Typed Client Facade
              │
              ▼
Go Desktop
  ├─ 窗口与托盘
  ├─ 系统文件选择/通知
  ├─ 凭据与设备身份
  ├─ Core 生命周期与健康检查
  └─ Wails 事件桥接
              │
              ▼
easyshare-core
  ├─ File Catalog
  ├─ Activity Store
  ├─ Transfer Router
  ├─ LAN Transfer
  ├─ Cloud Client
  ├─ Sync Engine
  ├─ Knowledge Gateway
  ├─ Local Cache
  └─ Event Stream
              │
              ├── 云端控制面 / RustFS
              ├── Python 知识计算面
              └── CfAPI / FileProvider Helper
```

### 13.3 进程职责

#### Vue UI

- 展示数据和收集用户意图；
- 维护选中项、当前路由、筛选和临时表单；
- 不保存长任务可靠状态；
- 不持有云端凭据；
- 不直接调用 RustFS、WebDAV 或 Python 服务。

#### Go Desktop

- Wails 窗口、托盘、拖放、系统通知和原生对话框；
- 探测、启动、复用和监控 Core；
- 使用 OS 安全存储保存登录凭据；
- 把 Core 事件桥接给前端；
- 不复制完整传输、同步和知识任务状态机。

#### easyshare-core

- 文件、任务、设备和同步状态的本机协调者；
- 长任务执行、持久化、恢复、重试和限速；
- 选择局域网或云端传输路径；
- 管理缓存、冲突和离线队列；
- 通过受控网关调用云端和知识服务；
- 向 UI、托盘和系统 Helper 提供版本化协议。

#### Explorer/Finder Helper

- 只负责平台要求的文件入口、占位、水合和状态回调；
- 通过版本化本机协议或 Named Pipe 与 Core 通信；
- 不直接发起云端请求；
- 不写 Core 业务数据库；
- 不在 Explorer/Finder 系统进程中运行耗时业务。

## 15. 状态同步与事件模型

### 15.1 真相源

- Core 持久状态是任务真相源；
- 云端控制面是跨设备文件元数据真相源；
- RustFS 是文件字节真相源，不是目录和权限真相源；
- Python 服务是处理执行者，不是文件权限真相源；
- Vue 状态只用于渲染和交互。

### 15.2 事件建议

```text
task.created
task.updated
task.removed
file.created
file.updated
file.removed
sync.status.changed
device.changed
knowledge.status.changed
service.status.changed
```

兼容期可以继续接收现有 `transfer.updated` 和云上传进度事件，由桌面桥接层归一化。迁移完成后，所有任务统一发送 `task.*`。

### 15.3 断线恢复

1. UI 首次启动获取完整或分页快照；
2. 记录快照游标/版本；
3. 建立事件订阅；
4. 断线时指数退避；
5. 重连后按游标拉取缺失事件，或重新获取快照；
6. 事件只用于快速更新，快照负责最终校准。

不得依赖“WebSocket 一定不丢事件”。

## 16. 本地持久化建议

### 16.1 近期

统一任务一期可以继续复用现有 Core 任务存储，通过接口隔离持久化实现，避免为 UI 改造同时引入数据库迁移风险。

### 16.2 中期

当以下能力进入实施时，再评估迁移为 Core 独占的 SQLite：

- 文件目录和稳定 `fileId`；
- 大量持久任务和批次；
- 同步游标与冲突；
- 本地缓存索引；
- 最近文件和离线元数据。

约束：

- 只有 Core 是 SQLite 写入者；
- Vue、Desktop、Shell 扩展和 Python 不直接共享写入同一数据库；
- 数据库迁移必须版本化、可回滚并在副本上验证；
- 跨进程访问通过 API/IPC，不通过共享文件锁协调。

## 17. Windows 与 macOS 系统入口路线

### 17.1 近期兼容入口

继续保留：

- Windows Shell NameSpace + loopback WebDAV；
- macOS Finder WebDAV 挂载；
- 应用内文件工作区作为完整管理入口。

该阶段目标是稳定品牌入口、打开行为和基础文件访问，不承诺占位文件与释放本地空间。

### 17.2 Windows 原生同步入口

CfAPI 采用独立 Helper 原型：

```text
Explorer / CfAPI
      ↓
easyshare-cfapi-helper.exe
      ↓ Named Pipe / versioned IPC
easyshare-core.exe
      ↓
云端控制面与对象存储
```

原型必须验证：

- 占位创建和目录枚举；
- 按需水合、取消和重试；
- 文件修改/重命名/删除回传；
- 固定到本机和释放空间；
- 状态图标；
- Core/网络不可用时 Explorer 不阻塞；
- 进程崩溃与升级后的恢复。

验收通过前不得替换当前入口。

### 17.3 macOS 原生同步入口

macOS 对等能力使用 FileProvider Extension，原则与 CfAPI 相同：

- 独立原生扩展；
- 与 Core 使用版本化协议；
- Finder 进程不承载业务逻辑；
- 独立处理签名、公证和 App Group 数据共享边界。

## 18. 安全与隐私

客户端演进必须同时补齐：

- 设备配对和信任撤销；
- 局域网传输认证与加密；
- 云端 Token 刷新、撤销和最小 scope；
- Windows Credential Manager/macOS Keychain 保存长期凭据；
- Shell Helper 使用本机身份认证，不能仅因监听 loopback 就无条件信任；
- 分享操作明确公开范围和过期时间；
- 知识检索在检索前应用授权文件范围；
- `docIds=[]` 必须表示无权访问并返回空结果，不能退化为全库检索；
- capabilities 不能替代服务端权限校验；
- 日志不得记录云端密钥、完整 Token、文档正文或公开分享密钥。

## 20. 分阶段实施路线

### C1：统一任务中心 + 首页工作台

目标：把客户端从功能展示页提升为可以持续使用的工作入口。

范围：

- 统一局域网发送/接收、云上传/下载任务；
- ActivityTask 基础契约；
- Core 任务持久化和状态事件；
- 首页最近活动与失败摘要；
- 全局活动抽屉；
- 全局上传入口；
- 拖放目的地选择；
- 任务重试、取消、打开文件/目录；
- 托盘活动摘要和系统通知。

验收：

1. 四类基础任务出现在同一列表；
2. 关闭主窗口后任务继续；
3. 重开窗口后状态与 Core 一致；
4. 断网显示“等待网络”，恢复后可继续；
5. 失败任务显示可操作原因并支持重试；
6. WebSocket 断开后快照能恢复正确状态；
7. 清理历史不影响运行中任务；
8. 批量任务可分组，并显示整体与单项结果。

### C2：文件目录层 + 文件工作区

范围：

- 稳定 `fileId + versionId`；
- 轻量目录层；
- 文件夹、面包屑、分页和搜索；
- 最近、收藏、分享、回收站；
- 右侧预览和 capabilities；
- 文件事件流；
- 缩略图缓存；
- 知识索引与文件版本关联。

验收：重命名、移动和恢复后文件身份不变；分享、任务和知识引用不依赖 object key。

### C3：同步文件夹 MVP

范围：

- 备份到云端；
- 双向同步；
- 本地监听和云端增量游标；
- 暂停/恢复；
- 重启恢复；
- 删除和重命名传播；
- 冲突副本与冲突中心；
- 缓存上限。

验收：任何无法自动判定的冲突都不静默覆盖。

### C4：知识入口

范围：

- 文件“加入知识库”；
- 解析/OCR/索引任务进入统一任务中心；
- 处理状态和失败重试；
- 文件名与内容搜索；
- 问答与来源引用；
- 引用跳转到页码/章节/表格/工作表/幻灯片；
- 权限感知检索。

验收：客户端不直接调用 `/lab`，任何回答都可追溯到授权文件版本。

### C5：原生文件入口原型

范围：

- Windows CfAPI Helper；
- macOS FileProvider Extension；
- 占位、按需下载和释放空间；
- 文件状态和右键动作；
- 离线与崩溃恢复；
- 与现有 WebDAV 入口并存验证。

验收：原型通过可靠性与性能门禁后，才讨论替换默认入口。

## 21. 第一轮建议实施切片

为了避免“同时改首页、文件模型、同步和知识”的大爆炸，C1 建议拆成四个可独立验收的切片：

### C1.1 统一任务契约

- Core Task 增加 kind、统一状态和操作能力；
- 云上传/下载注册到 Core 任务存储；
- 保持旧任务数据兼容；
- 增加状态机、持久化、重启恢复和 API 测试。

### C1.2 全局活动抽屉

- 顶栏增加活动按钮；
- 所有页面可展开；
- 展示四类任务；
- 支持失败详情、重试、取消和打开；
- 现有传输页面转为完整历史视图。

### C1.3 首页工作台

- 最近文件/最近操作；
- 进行中和需要处理的任务；
- 全局上传入口；
- 空间、设备和网络摘要；
- 空状态和错误恢复入口。

### C1.4 全局拖放路由

- 明确目的地区域直接执行；
- 无明确目的地时展示 DestinationPicker；
- 多文件和文件夹使用批次任务；
- 危险操作不使用记忆默认值；
- 对无权限、离线和空间不足返回可操作提示。

每个切片都应按项目迭代流程建立独立记录、测试和回滚说明，不合并为无法审查的大型改动。

## 24. 产品质量指标

建议使用以下指标判断客户端是否真的变成熟，而不是只看页面数量：

- 从启动到发起上传/发送不超过两次主要交互；
- 任何长操作发起后立即出现可见任务反馈；
- 客户端重新打开后任务状态与 Core 一致；
- 可恢复错误都有明确重试入口；
- 不可恢复错误都有原因和建议动作；
- 用户无需输入 IP、端口、对象 key 或知识管线参数；
- 搜索或知识回答可定位到稳定文件版本；
- Explorer/Finder 集成故障不拖垮主客户端与 Core；
- 核心文件操作可用键盘完成；
- 任务、文件和权限状态在不同入口中的语义一致。

## 25. 风险与控制

| 风险 | 结果 | 控制方式 |
| --- | --- | --- |
| 一次性重写全部 UI | 改动大、难验收、回归多 | 按 C1.1-C1.4 独立切片 |
| 任务只存在前端 | 关闭窗口后丢状态 | Core 持久化，UI 快照恢复 |
| 事件被当作真相源 | 断线后界面漂移 | 事件快速更新 + 快照校准 |
| 使用 object key 作为身份 | 重命名、版本、分享和索引失效 | 稳定 fileId/versionId |
| 多进程写同一 SQLite | 锁竞争、损坏和升级困难 | Core 单写者 + API/IPC |
| UI 直连 Python 或 RustFS | 权限、凭据和重试分散 | 统一通过 Core/控制面 |
| 过早替换 WebDAV | Explorer 可靠性风险 | CfAPI/FileProvider 独立原型并存 |
| 参考 WPS 变成复制 WPS | 产品臃肿、失去差异化 | 只借鉴文件入口和反馈体系 |
| capabilities 代替鉴权 | 可被绕过 | 服务端每次强制权限校验 |
| 同步冲突静默覆盖 | 用户数据丢失 | 默认保留两个版本并进入冲突中心 |

## 26. 排障与决策规则

后续实施出现问题时按以下规则定位，避免重复争论：

### UI 与实际任务状态不一致

1. 先读取 Core 任务快照；
2. 再检查事件订阅和断线重连；
3. 以 Core 持久状态为准修正 UI；
4. 不通过在前端增加另一份任务状态机“补丁式修复”。

### 重试后出现重复任务或重复对象

1. 检查 `operationId`/idempotency key 是否稳定；
2. 检查创建任务与上传会话是否原子关联；
3. 检查完成回调重复到达时是否幂等；
4. 不通过隐藏重复项掩盖数据问题。

### 重命名后分享、同步或知识引用失效

1. 检查功能是否仍使用路径/object key 关联；
2. 改为 `fileId + versionId`；
3. 对旧引用建立迁移或兼容映射；
4. 不禁止重命名来规避身份模型缺陷。

### WebSocket 断线后进度不动

1. 检查指数退避重连；
2. 检查可见窗口恢复时是否立即拉快照；
3. 检查事件游标或全量校准；
4. WebSocket 永远不是唯一可靠状态来源。

### Explorer/Finder 卡顿

1. 检查扩展是否同步等待网络；
2. 检查是否在系统进程中执行解析、上传或数据库写入；
3. 将耗时工作移回 Core；
4. 为 Helper 设置明确超时、取消和降级状态。

### 知识回答引用旧版本

1. 检查索引是否绑定 versionId；
2. 检查新索引是否在完整构建后再切换；
3. 检查权限过滤是否在检索前应用；
4. 未完成新版本索引时明确展示“内容索引更新中”。

## 27. 明确暂不实施

在基础模型稳定前，不做：

- 更换 Wails/Vue/Go 技术栈；
- 完整 Office 文档编辑器；
- WPS 模板市场或办公门户；
- UI 直接嵌入生产版 `/lab`；
- UI 直接连接 RustFS；
- 让 WebSocket 成为唯一状态源；
- 多个进程共同写业务 SQLite；
- 未经原型验收就以 CfAPI/FileProvider 替换 WebDAV；
- 同一轮同时上线账号、同步、知识、WPS 插件和原生占位文件。

## 28. 后续需要单独决策的问题

以下内容在相应迭代开始前通过 ADR 或迭代文档确认：

1. Core 任务持久化从 JSON 迁移 SQLite 的具体门槛与迁移方式；
2. 文件目录控制面由本地 SQLite 先行还是直接接入 Java/PostgreSQL；
3. 云端中转发送的生命周期、配额和目标设备领取协议；
4. 跨设备文件事件使用游标拉取、WebSocket、消息推送或组合方案；
5. Windows CfAPI Helper 的实现语言、部署和升级边界；
6. macOS FileProvider 的 App Group、签名和 Core 通信方式；
7. WPS 插件采用云端 API 还是受限本机桥接；
8. 最近文件与搜索历史的隐私保留策略；
9. 企业环境下缓存加密、远程擦除和设备撤销策略。

## 29. 结论

EasyShare 客户端下一阶段的关键不是增加更多独立功能页，也不是更换技术栈，而是建立统一的文件、目的地和活动模型。

推荐执行顺序固定为：

```text
统一任务中心与首页工作台
    ↓
稳定文件身份与文件工作区
    ↓
同步文件夹
    ↓
知识入口
    ↓
CfAPI / FileProvider 原生入口
```

WPS 提供的是成熟文件客户端的交互参考；EasyShare 的差异化则是把云端、局域网、同步和知识处理连接为一条连续、可恢复、可解释的文件工作流。
