- **【已修复】回收站曾在读侧失效（2026-10-16）**：软删只改目录行、不动 RustFS 对象，而列表出口**没按 state 过滤**——存储列举里照样有这条对象，惰性补账于是给它 insert 一条新的 active 行，等于**列表自己把删除撤销**。三重症状：①删掉的文件照旧在列表里；②还原永远报「原位置已有同名文件」（占位者正是列表自己插的那行，用户看不见也删不掉）；③彻底删除时引用计数认为还有债主，**对象永不释放**。修复把列表三步（查库 → 按 state 隐藏 → 补账回填）**收成唯一公开入口** `DriveFileService.list(...)`（另两步降 `private`，从编译期杜绝「漏一步」）；状态判定走白名单（只有 `active` / `state IS NULL` 算在用）。5 条用例均先证明「去掉修复即失败」再通过。详见 [`known-issues.md`](known-issues.md) KI-10。
