# 2026-10-21 · 会议纪要 skill 长会实测复盘

上一轮 [`2026-10-21-会议纪要skill提速与区间转写.md`](2026-10-21-会议纪要skill提速与区间转写.md) 的「下一步」写明：用真实宿主跑一场 30 分钟以上的会，对比默认两步走 / `--no-topics` / `--split-topics`。本轮就是那次实测的复盘与整改。

## 实测现场

用户把 `skills/minutes-from-transcript` 单独复制给一个 Agent，宿主模型 **Qwen3.8-27B-NVFP4**（约 32K 级窗口，子代理与主模型同窗口），输入一场 **59 分钟** 会议，压缩后材料 **15960 字 / 71 行**。全程 **89 分钟**，中途还出现子代理**上下文耗尽**。

| 时刻 | 事件 | 耗时 |
| --- | --- | --- |
| 15:42:56 | 读 SKILL.md/README、环境检查（Python 3.12.4） | ~2 min |
| ~15:45 | `pip install -e .` → minutecraft 0.1.0 | <1 min |
| ~15:46–15:50 | 单段模式 prepare；写 answers.json；确认浏览器 | ~3 min |
| 15:50 → 16:03:28 | summary 子代理完成（9604B） | 13.5 min |
| ~16:05 | **topics 子代理上下文耗尽、零产出** | 浪费 10–15 min |
| ~16:06 | 改走 `--split-topics` 重 prepare，复用 summary 答案 | ~1 min |
| 16:07 → 16:24:13 | outline 子代理（输入 44KB、输出仅 1.4KB） | 11.5 min |
| ~16:25 → 16:49:39 | `expand` 拆 8 个扩写请求并发，最慢 3 个落盘 | ~13 min |
| 16:37:33 | **finish 早跑一次 exit 2**（topic-1.json 尚未落盘） | ~1 min |
| ~16:55 | finish 第二次：exit 0、0 警告、5 产物 | ~1 min |
| ~16:58 | **render exit 3：拼接段 `NameError: 'Image'`** | ~2 min |
| 17:02 | 修 render.py 后重跑：8.37s 出 1080×15589 PNG + PDF | ~4 min |
| 17:05–17:12 | 校验 docx（64 段/6 表）、抽查 minutes.md、交付 | ~5 min |

按损失排序：单段 topics 爆上下文 + 被迫重走大纲腿 **≈25 min**（最大头）；三次长输出处方（summary 13.5 / outline 11.5 / 最慢扩写 ~13）**≈40 min** 纯推理；render 缺陷 **≈4 min**；早跑 finish **≈1 min**。理想路径（一开始就 split、无缺陷）测算 **≈30 min**，可省 ≈55 min。

## 根因

1. **默认单段 topics 在 32K 级宿主的子代理上必爆**。账是：材料 ~16k 字 + 提示词 ~10-12k tokens + 子代理自身开销 ~8-10k + 输出 6-10k tokens，贴着窗口上限。引擎此前只在 `plan.note` 里说「topics 最慢」，没有把「这份材料该走两阶段」这件事说出来——慢是可以忍的，**跑完发现零产出**才是致命的。
2. **`render_png` 拼接段的 `NameError` 是必然缺陷，不是偶发**：`from PIL import Image as image` 把类绑到小写哨兵，拼接处引用的却是大写 `Image`。只有 >12000px 的长报告走得到这条分支，而既有测试全部走短页路径，所以发布时没人发现。同一份逻辑在 `report/render_report.py` 里是**写对的**——那份是无人 import 的死副本。
3. **子代理「汇报已写入」≠ 文件已落盘**：agent 侧缺一条 finish 前对账的规矩。
4. **大纲腿用全量材料换了一个 1.4KB 的答案**：`topics_outline.user.txt` 44KB 输入、输出仅 1.4KB，切分只需要时间锚点与句意开头，不需要逐字正文。

## 设计决策

1. **修 `render_png` 拼接段**（`engine/minutecraft/render.py` · `render_png`）：删掉 `image = None` 哨兵与 `assert image is not None`，直接 `from PIL import Image`。Import 失败分支已经抛 `ReportRenderError`，后面的引用不可达，不需要哨兵。
2. **给拼接分支补真实回归**（`engine/tests/test_engine.py` · `test_render_png_stitches_segments_beyond_shot_limit`）：用假 `PIL` 模块 + 打桩 `_measure_height` / `_shot` 跑通 >`MAX_SHOT_HEIGHT` 路径，并断言分段高度、拼接偏移与临时文件清理；另加一条没装 Pillow 时**截图之前**就失败、不留半成品的用例。缺陷类型是「名字没绑上」，只有真跑到那条分支才能抓住，读代码容易一路放过。
3. **删死副本**（原 `engine/minutecraft/report/render_report.py`）：出图走的是 `engine/minutecraft/render.py`，`engine/minutecraft/cli.py` · `cmd_render` 只 import 它；那份副本全仓无人引用，留着只会让人以为有两套出图实现要同步——正是上一轮「同步义务要按产物写」那条教训的反面。`report.html` 模板保留。
4. **`prepare` 给出 split-topics 建议但不改默认**（`engine/minutecraft/engine.py` · `prepare` / `SPLIT_RECOMMEND_MIN_CHARS` / `SPLIT_RECOMMEND_MIN_MINUTES`，`engine/minutecraft/cli.py` · `cmd_prepare`）：材料字数 ≥9000 或时长 ≥35 分钟、且当前走单段 topics 时，`plan.recommend` = `split-topics` 并附原因，`plan.note` 与 CLI 的 `next` 第一行同步点名。**为什么不自动切**：阈值是从一次失败反推的，不是普适规律；自动改默认路径会让「短会一次往返」这条已验证的快路随阈值漂移，而 `next` 里的明确指令对 Agent 的约束力已经足够。
5. **新增 `--lean-outline`（实验项，默认关）**（`engine/minutecraft/models.py` · `render_skeleton` / `_blocks`，`engine/minutecraft/textutil.py` · `head_sentence`）：大纲腿的材料只保留「说话人 + 段首时间戳 + 每段首句」，扩写腿仍吃精确时间窗的完整片段，所以代价只可能是**议题切边位置**，不是正文质量。`material.outline_chars` 报的就是大纲腿真实吃进去的字数。
6. **Agent 侧落盘对账规矩写进 SKILL.md**：并发子代理回执要求「实测字节数」而不是自报；`finish` 前先列目录对账，`exit 2` + `@文件` 不存在时先判「还没写」而不是「答案丢了」。

## 兼容与迁移

- 产物结构不变；`plan` 新增 `recommend` / `recommend_reason` 是加法字段，旧调用方忽略即可。
- 旧请求包（`topics_mode=single`）继续可被 `finish` 接受。
- `Transcript.render` 抽出块合并逻辑供 `render_skeleton` 复用，签名与默认行为不变。
- 删除 `report/render_report.py` 不影响 CLI 与知识服务（无人 import）；`check_skill_sync.py` 的 `--apply` 不删文件，需手工删 skill 副本那一份。

## 实测后的下一步

1. 让宿主拿同一场 ≥40 分钟的会跑三组：单段（对照，预期子代理零产出）/ `--split-topics` / `--split-topics --lean-outline`，对比墙钟与议题数、切边位置；`lean-outline` 只有在切边不明显变差时才升为默认。
2. 阈值 9000 字 / 35 分钟是从**一次**失败反推的，样本量 1。第二次实测（不同窗口、不同宿主）若给出不同的临界点，改常量并回写本文件。
