## 背景与问题

部署后同事要记两套账号：① 桌面客户端的**控制面账号**（RuoYi 管，管理页开通）；② 知识页问答
/WPS 插件/浏览器 /lab 用的**知识服务账号**（deploy.sh 向导批量开通）。9-06 分发冲刺做了缓解
（知识页账号按登录名预填），但密码仍是两套、互不同步。

## 方案：introspection 信任（非本地验签）

RuoYi-Vue-Plus 的令牌是 Sa-Token + Redis 的**不透明随机串**（非自包含 JWT），知识服务本地
无法验签——信任方式只能是回查：`GET {控制面}/system/user/getInfo`，200 即令牌有效，顺带取回
用户名/部门/管理员标志。请求头（`Authorization: Bearer` + `clientid`）与响应解析同 Go 客户端
`internal/account/client.go` 一套（桌面端已在生产验证该形状）。

- **配置**：`.env` 加 `CONTROL_PLANE_URL`（空=关闭，行为与现状完全一致）+
  `CONTROL_PLANE_CLIENT_ID`（默认 RuoYi 内置 PC 客户端）。标准部署同主机，deploy.sh /
  deploy.ps1 生成 .env 时默认写 `http://127.0.0.1:8090`。
- **缓存**：introspection 结果缓存 60 秒（上限 512 条），命中不回查——观察期规模每请求一跳
  控制面不可接受，长缓存又会拖慢登出生效，60s 是折中。
- **JIT 建档**：控制面新用户首次过票即建本地档案（owner/部门过滤与用户列表依赖本地行）；
  role 按控制面 superadmin/*:*:* 判定（同 Go IsAdmin 口径），dept 取控制面 deptId。
- **权属划分**：本地已有同名人 → **保留本地 role**（管理页显式管理的语义不被 SSO 覆盖），
  **dept 跟随控制面**（组织架构权威在控制面，与部门授权片 1 的 sys_dept 投影同源）。
- **本地登录不受影响**：中间件先查本地令牌（SQLite tokens 表），未命中才回查——两个随机
  空间无歧义；WPS/浏览器用户与 admin 备用通道照旧走本地账号。

## 实现

- `app/auth/sso.py`（新）：`ControlPlaneSSO`——resolve/introspect/JIT/缓存；
- `app/config.py`：`control_plane_url` / `control_plane_client_id`；
- `app/services.py`：AppServices 加 `sso` 字段，build_services 按 URL 非空装配；
- `app/main.py`：auth 中间件本地未命中后回查 SSO（run_in_threadpool，不阻塞事件循环）；
- 部署资产：`.env.example`、`deploy.sh`、`deploy.ps1` 三处 .env 生成默认写 SSO 配置；
  DEPLOY-CHECKLIST §2 更新（控制面一套账号即可，WPS/浏览器用户仍需同名本地账号）；
  server-linux README §五、architecture.md 知识服务 auth 段同步。

## 边界与后续（不做清单）

- **客户端免登不在本片**：桌面端「知识」页仍走 Core 网关的登录代理（用户输一次知识服务
  密码或同名本地账号）——SSO 打通后下一片可让 Core 直接透传控制面令牌，知识页完全免登；
- WPS 窗格登录不变（本地账号）；控制面登出后知识服务侧缓存最多 60s 内仍认旧票（可接受）；
- 控制面不可达时 SSO 令牌全部拒绝（fail-closed），本地令牌不受影响——内网同主机部署下
  控制面不可达即整体故障，无降级意义。
