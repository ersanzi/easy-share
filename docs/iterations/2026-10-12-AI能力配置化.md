# 迭代记录 — AI 能力管理端配置化（2026-10-12，用户直配）

> 触发：会议听记切片交付后，用户提出「AI 能力在 Java 管理端要做个配置项」。
> 调研结论（分层+缓做）被用户推翻拍板：**直接做成管理端配置化**。

## 背景与问题

听记/知识问答的 AI 配置（LLM 供应商/key/模型、ASR 开关）当前在知识服务 `.env`，
部署时一次性生成，变更需 ssh 改文件+重启。多客户部署后远程运维成本高，客户侧
superadmin 无法自助。目标：管理端（桌面端管理页）可视化查看与修改，保存后尽量
热生效，控制面 sys_config 为权威源。

## 方案

- **存储**：控制面 `sys_config` 单键 `drive.service.ai.config` 存 JSON
  （llmBaseUrl/llmModel/llmApiKey/asrEnabled/asrSpeakerEnabled）；密钥明文入库存档
  的安全边界=同机部署下 DB 访问本就等价于持钥（与 .env 同级），访问面用
  superadmin 收口；GET 对 UI 一律掩码显示。
- **下发通道**：共享服务密钥（sys_config `drive.service.ai.secret` ↔ 知识服务
  `.env CONTROL_PLANE_SERVICE_SECRET`，deploy 脚本生成两侧同值）。
  控制面 PUT 保存后**同步推送**到知识服务 `PUT /admin/ai-config`（X-Service-Secret
  头），推送失败不阻断保存，结果作为 warning 回 UI（重新保存即重推）。
  知识服务本地 `data/runtime_config.json` 存覆盖层（update.sh 数据目录持久化，
  重启不丢）；不做启动拉取（推送失败重存即可，通道减半）。
- **热生效**：知识服务以「overlay 覆盖 .env 生成新 Settings」的方式重建 LLM 消费
  组件（RAG Generator、听记 Summarizer、Contextual Builder、MultiHop 裁判），
  进行中请求持旧引用自然完成；ASR 开关热构建/拆除 meetings 组件。
- **不做**：embedding/rerank 配置化（改 dim 会损坏向量索引，留部署期配置）；
  启动时回拉控制面；密钥加密存储（同机部署收益低，挂运维切片重评估）。

## 实现

- **知识服务**：`app/ai_config.py`（AiConfigStore 覆盖层原子落盘 / apply_overlay 生成生效 Settings / normalize_overlay 校验 / 密钥掩码）；`app/admin/routes.py`（`PUT /admin/ai-config`，X-Service-Secret 头 hmac 比对，llmApiKey 空串=沿用现有覆盖值防误清）；`services.reload_ai_components()`（LLM 变更→重建 Generator/MultiHop/ContextualBuilder；ASR 开关变更→热构建/拆除 meetings 组件；进行中请求持旧引用自然完成）；build_services 启动时加载 overlay；config 增 `control_plane_service_secret`/`runtime_config_path`。
- **Java 控制面**：`AiConfigController`（`/easyshare/service/ai-config` GET/PUT，超管；sys_config `drive.service.ai.config` 存 JSON 为权威 + `drive.service.ai.secret` 推送密钥；GET 掩码回显，PUT 时 apiKey 留空=保留旧值；保存后 JDK HttpClient 推送知识服务，失败不阻断保存）。**配置体是固定 5 字段平铺 JSON，模块编译期无 JSON 库，按固定形状手写序列化/正则解析**（hutool-json 不在 classpath）。
- **Go/前端**：account 客户端 AiConfig/SetAiConfig + App 绑定 AdminAiConfigGet/Save；AdminPanel 新增「AI 能力」卡片（LLM 地址/模型/密钥掩码 + 听记与说话人开关 + 推送结果提示）。
- **部署资产**：deploy.sh 知识服务 .env 生成段加 `CONTROL_PLANE_SERVICE_SECRET`（已有 .env 沿用旧值、缺则 openssl 随机生成）+ 幂等写入控制面 sys_config（PG 容器就在脚本手里；config_key 无唯一约束，NOT EXISTS+UPDATE 双段式）。

## 排障实录（重要坑）

- **JDK HttpClient 默认 HTTP/2 语义 vs uvicorn**：Java 推送到知识服务稳定 422，但同 body 的 curl 是 200——根因是 JDK 客户端对明文地址默认尝试 h2c 升级（请求带 `Upgrade: h2c` + `Connection: Upgrade, HTTP2-Settings`），uvicorn/h11 对该请求回 422。修复：推送客户端钉死 `HttpClient.Version.HTTP_1_1`（对照实验：带 h2c 头 422、`--http1.1` 200）。以后任何 Java→uvicorn 的直推都要记得这个坑。
- 本机排障时发现 **8090 被 blade-api 调试实例占用**（另一项目抢了 EasyShare 文档端口），run-ruoyi-admin 起不来——端口探活返回 200 不代表是自家服务，要查进程身份。

## 边界与不做清单

- embedding/rerank 不开放配置化（改 dim 会损坏既有向量索引，留部署期配置）
- 密钥明文存 sys_config：同机部署下 DB 访问等价于持钥（与 .env 同级），不做加密存储；多客户/密钥托管需求出现时重评估
- 控制面不可达/推送失败：配置已保存，UI 明示，重新保存即重推；不做启动回拉、不做定时轮询
- LLM 连通性预检按钮（保存前试呼）留作后续小件
