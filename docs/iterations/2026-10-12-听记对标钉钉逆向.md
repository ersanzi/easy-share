## 一、逆向过程与发现

### 1. REA 工具评估与路线修正
REA 是 MCP 驱动的逆向工具（Electron/网站/二进制分析）。实际排查结论：**本机钉钉 8.x 不是 Electron 应用**——原生 C++ 壳（MainFrame.dll）+ 云端 web 页（业务代码不在本地），REA 的 Electron 拆包模式无用武之地；听记页在登录墙后，网站模式也够不着。逆向路线改为三层：**本地残留分析 + 活体服务探测 + 官方文档/发布说明**。

### 2. 本机取证（D:\Program\DingDing\main\current_new + %APPDATA%\DingTalk）
- 导航配置 `configurations/navigator/default_navigator_v5.json`：听记 tab = `AI听记`（i18n key `pctab_h5_memo`），入口 **`https://memo.dingtalk.com/desktop_x.html#/desktop`**（pre 环境 pre-memo.dingtalk.com）——听记内部代号 **memo**。
- `memo.dingtalk.com` 未登录返回登录壳（h5-dingtalk-login），业务 bundle 全部在鉴权后加载，静态侧无资源可拆。
- **`%APPDATA%\DingTalk\mcp_port` = `{"http_port": 8440, "pid": ...}`：钉钉在本机常驻一个 MCP 服务**，`POST 127.0.0.1:8440/mcp` 返回标准 JSON-RPC 2.0（无 Authorization 头报 `-32600 access denied`）——即客户端里「让你的 AI 工具帮你写周报、追待办、做分析…立即连接」的后端。配对令牌只在客户端 UI 生成，本地无落盘。
- 崩溃转储目录（%LOCALAPPDATA%\DingTalk）只有历史版本 dump；DingTalk_1xx 是 Chromium 用户档案。

## 三、本轮实现

**听记 AI 问答**（全栈级联）：
- 知识服务：`summarizer.ask_text`（多轮纯文本，max_tokens=4096）+ `service.ask`（纪要/要点/待办/转写全文装配进上下文，历史截 6 轮，系统提示限定只依据听记内容）+ `POST /meetings/{id}/ask`。
- Go 四层：knowledge client `MeetingAsk` → Core 代理 `knowledgeMeetingAsk`（清写超时 + knowledgeQueryTimeout）→ desktop `MeetingAsk`（slowRequest）→ App 绑定 `MeetingAsk`。
- 前端：详情页改双栏（主栏 + 280px 侧栏），问答气泡 + 3 个推荐提示词 chip（总结关键结论/未闭环事项/起草跟进邮件）+ 输入框，切会议自动清空会话。

**导入文件**：`recorder.ts` 新增 `decodeAudioFileToWav`（AudioContext.decodeAudioData 支持 wav/mp3/m4a/flac/ogg → 下混单声道 → 复用 resample/encodeWav 到 16k WAV），录音卡加「导入文件」按钮，100MB 上限，走既有上传通道，后端零改动。

**质感三件**：录音卡模板先行 chips（7 场景 emoji+描述）；列表行 AI 摘要预览（66 字截断）；详情页 sections 章节锚点导航。
