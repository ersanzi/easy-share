# 产品定位与破局（战略讨论结论）

> 源起：2026-08-20 起的多轮战略讨论（起因："这套东西有价值吗？市面上有类似产品吗？"）。
> 本文是讨论的沉淀与执行决策，与 [`product-vision.md`](product-vision.md)（桌面端愿景）互补，定位为知识平台主线的方向真相源。
> 状态：随讨论与验证推进持续修订。最后更新：2026-08-20。

## 一、市场判断（讨论结论）

**不做通用"企业知识库平台"**——该赛道三层拥挤：国际（Glean $7.2B、Copilot）、国内套件内嵌（飞钉/WPS/ima，数据在云）、开源自部署（MaxKB 15k star/RAGFlow/Dify，需运维）。solo 正面进场无胜算。

**结构性空白**：20-500 人、数据敏感（内网/涉密）、无运维能力的团队——付不起鸿翼（项目制数十万起）、不敢上云（排除飞钉/ima）、装不动开源（排除 MaxKB）。四类玩家**结构性**够不着这一层。

**对标来源（鸿翼）的启示**：鸿翼用 25 年占据中大型制造业 ECM/知识管理，其公开软肋（重量级/项目制/高客单/需 IT 团队）恰是空白层的成因；其推出 InDrive 下探轻量市场，验证了空白层真实存在。鸿翼客户中设计院/制造业密集，证明该客群**有付费习惯**，只是中小厂买不起。

## 二、定位（当前假设，待种子发芽后修订）

> **EasyShare 知识平台 = 中小制造企业的私有知识服务器：文件在哪，知识就从哪开始；数据不出厂；装上就用。**

- **种子用户**：自己公司（30 人 IT 公司，钉盘/微信/各人电脑文件沼泽）——先让产品在自己公司每天被用。
- **目标客群**：中小制造业（约 20-500 人；接触面有几百家，经 IT 服务关系触达）。
- **交付形态**：本地部署优先（未来可一体机/上云，灵活支持）；**不卖软件，借 IT 服务关系交付**（帮厂里做信息化时顺带部署，含运维服务费）——制造业买系统难，接受方案容易。
- **差异化四层**（分工明确）：
  | 差异点 | 层面 | 打动谁 |
  | --- | --- | --- |
  | 私有知识服务器（一体机/本地） | 商业模式 | 老板（数据不出厂） |
  | 文件沼泽一键变知识（目录监听自动入库） | 产品 | 全员（第一次见效时刻） |
  | WPS 里知识找人 | 体验 | 天天写文档的人 |
  | API/MCP 知识服务（已落地） | 生态 | 对接业务系统的人 |
- **内网传输**保留为入口功能，不作为核心卖点（免费工具存在）。

## 三、发芽路线（执行决策，2026-08-20 定）

原则：**产品是种子，先发芽再回答战略问题**（用户原话精神）。发芽 = 自己公司真实使用。

1. **薄控制面 2a：账号与登录**——多人使用的地基，文件归属/权限的前置。默认关闭（`AUTH_ENABLED=false`），不影响现有行为。→ 2b 文件归属、2c 权限感知检索（`doc_ids` 钩子已就位）。
2. **共享盘目录监听自动入库**——"文件沼泽一键变知识"的引擎。
3. **桌面端集成知识问答**——知识入口长进桌面端。
4. **WPS 最小闭环**——现场演示的"哇"时刻。

Java 控制面推迟到多租户/规模化真实需要时拆分（接口按可拆设计；SQLite 为过渡真相源，与架构文档一致）。
