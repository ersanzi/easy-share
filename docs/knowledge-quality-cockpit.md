# 知识质量驾驶舱：设计文档

> 里程碑 1.8 的核心交付物。把 `/lab` 从开发冒烟台升级为产品质量验证工具。
> 最后更新：2026-07-30

## 1. 设计哲学

**不是管线调试器，是知识质量驾驶舱。**

调试器问"这个 chunk 为什么没被检索到？"（开发者视角）。
驾驶舱问"员工问了一个真实业务问题，系统给的答案能不能直接用？如果不能，问题出在哪一环？"（产品视角）。

核心交互循环：

```
输入真实业务问题
    → 系统展示完整"思考过程"
    → 用户判断答案质量
    → 如果不好，一键定位瓶颈环节
    → 修复后重新验证
```

## 2. 四层架构

### 第一层：单文档透视（"这份文档处理得好不好？"）

**入口**：上传文档 / 选择已入库文档。

**布局**：左右分栏。

| 左栏（原文） | 右栏（管线产物） |
| --- | --- |
| PDF 页面渲染 / Office 原始排版 | 三个 Tab 切换 |

右栏三个 Tab：

- **结构化块**：解析出的 DocumentBlock 列表（标题/段落/表格），每块标注页码、提取方式（text_layer / ocr）、OCR 置信度。点击块 → 左栏对应区域高亮。
- **清洗 Diff**：clean.md 与原始渲染的对比视图。被清洗规则删除的内容（页眉页脚/页码/PII）用删除线 + 红色背景标注，附规则名称和命中计数。让用户一眼看到"清洗动了什么、该不该动"。
- **切块地图**：clean.md 全文上叠加 chunk 边界色块。每个 chunk 用不同颜色标注，hover 显示：chunk ID、所属章节上下文（`[标题层级]`）、来源页码、字符数、包含的 block_ids。点击 chunk → 左栏对应原文区域高亮滚动。

**关键交互**：右栏任何元素 → 左栏原文定位。这就是"回溯"——从管线产物反查到原始文档的精确位置。

### 第二层：检索策略对比台（"搜出来的东西对不对？"）

**入口**：输入一个业务问题。

**布局**：上方问题输入框 + 下方四列并排对比。

| 列 | 策略 | 展示内容 |
| --- | --- | --- |
| A | 纯向量检索（Milvus cosine） | Top-K 结果列表，每条：文档名、页码、score、chunk 文本（关键词高亮） |
| B | 纯关键词检索（BM25） | 同上 |
| C | 混合检索（向量 + BM25 融合） | 同上，标注每条结果来自哪路召回 |
| D | Agent 多跳 | 展示检索轮次：第一轮 query → 结果 → 判断不够 → 第二轮 query → 补充结果 → 合并 |

**对比视图**：

- 高亮"只有某一路命中"的结果（说明单一策略有盲区）
- 标注最终答案因策略不同而产生的差异
- 每条结果可展开查看：完整 chunk 文本、metadata、所属章节上下文、在原文中的位置（跳转第一层）

**引用溯源**：点击任何检索结果 → 弹出原文对照视图（chunk 文本 vs 原文对应段落），验证"切块有没有切断上下文"。

### 第三层：生成质量审计（"AI 有没有编？"）

**入口**：在第二层选定检索策略后，点击"生成回答"。

**布局**：三栏。

| 左栏：Prompt 透视 | 中栏：AI 回答 | 右栏：忠实度审计 |
| --- | --- | --- |
| 完整 system prompt | 生成的回答文本 | 逐句分析 |
| 检索到的 context（按 score 排序） | 每句话后标注引用来源 | 每句标记：✅ 有依据 / ⚠️ 部分依据 / ❌ 无依据 |
| 用户问题 | 引用可点击跳转 | 无依据的句子标红 = "疑似幻觉" |

**忠实度检查逻辑**（初版，不依赖额外模型）：

1. 将 AI 回答按句拆分
2. 对每句提取关键实体和数值（正则 + 简单 NER）
3. 在检索到的 context 中搜索这些实体/数值
4. 匹配到 → ✅；部分匹配 → ⚠️；完全未匹配 → ❌
5. 后续可升级为 NLI entailment 模型判断

**Context 充分性判断**：

- 如果 AI 回答中 ❌ 比例 > 30%，提示"检索 context 可能不充分，建议启用多跳检索或扩大 Top-K"
- 如果所有 context 都未被引用，提示"检索结果与问题可能不相关，建议检查 embedding 质量或查询改写"

### 第四层：知识健康度仪表盘（"一万份文档扛不扛得住？"）

**入口**：仪表盘首页（无需输入问题）。

**五个度量维度**：

| 维度 | 指标 | 数据来源 |
| --- | --- | --- |
| 覆盖率 | 各业务领域文档数量分布；无文档覆盖的领域标红 | 文档 metadata + 人工标注领域标签 |
| 新鲜度 | 文档最后更新时间分布；超过 N 天未更新的占比；引用已废止法规的文档列表 | 文件 mtime + 版本历史 |
| 一致性 | 文档间矛盾检测结果（同一实体在不同文档中的描述不一致） | 跨文档实体匹配 + LLM 判断 |
| 使用率 | 各文档被 AI 检索/引用的频次；从未被命中的"僵尸文档"列表 | 检索日志统计 |
| 盲区 | 用户查询中无法给出有效答案的问题聚类；按主题分布 | 查询日志 + 低分结果统计 |

**批量压测**：

- 上传一批文档（或指定 RustFS 已有文件）
- 运行预设问题集（42 条评测集 + 自定义）
- 输出：recall@k / MRR / snippet_hit 分布图、按文档类型（Word/Excel/PDF/PPT/扫描件）分组的命中率、按检索策略分组的对比
- 识别短板："扫描件 PDF 的 recall 比 Word 低 23%，建议优化 OCR 后处理"

## 3. 后端 API 设计

所有 API 在 `/debug/` 路径下，仅回环可访问（与 `/lab` 同策略）。

```
GET  /debug/document/{file_id}
     → 结构化块列表 + 清洗 diff + chunk 列表及 metadata

GET  /debug/document/{file_id}/chunks
     → chunk 列表（含 text、block_ids、source_locations、章节上下文）

GET  /debug/chunk/{chunk_id}/source
     → chunk 对应的原文位置（页码 + bbox / 段落索引）

POST /debug/query
     body: { question, strategies: ["vector","bm25","hybrid","multihop"], top_k }
     → 各策略的检索结果并排返回（含 score、metadata、chunk 全文）

POST /debug/generate
     body: { question, strategy, top_k }
     → 完整 prompt + AI 回答 + 逐句忠实度分析

GET  /debug/health
     → 知识健康度五维指标（覆盖率/新鲜度/一致性/使用率/盲区）

POST /debug/batch-eval
     body: { file_ids?, questions?, strategies? }
     → 批量评测聚合指标（按文档类型 × 策略交叉）
```

## 4. 前端技术选型

保持轻量，不引入重型框架：

- **Jinja2 模板 + Alpine.js + Tailwind CSS**（与现有 `/lab` 一致的技术栈）
- 多 Tab SPA 体验（Alpine.js 的 x-show 切换，无需路由库）
- 原文渲染：PDF 用 pdf.js，Office 用转换后的 HTML
- Diff 视图：jsdiff 库
- 图表（健康度仪表盘）：Chart.js

不引入 Vue/React——这是内部验证工具，不是面向客户的产品 UI。

## 5. 分期计划

**第一期（里程碑 1.8 核心）**：

1. 单文档透视（结构化块 + 清洗 Diff + 切块地图）
2. 检索调试（纯向量，展示 score + metadata + 溯源）
3. 生成审计（prompt 透视 + 逐句忠实度标注）

**第二期（里程碑 1.8 完善）**：

4. 检索策略对比（BM25 + 混合 + 多跳并排）
5. 知识健康度仪表盘（五维指标）
6. 批量压测（文档类型 × 策略交叉矩阵）

**第三期（里程碑 1.9 联动）**：

7. 在驾驶舱中验证 Reranker 增益（排序前后对比）
8. Agent 多跳检索的轮次可视化
9. 知识原子萃取的初步展示（从 chunk 中标注原子边界）

## 6. 与现有 /lab 的关系

`/lab` 保留为快速冒烟入口（上传 → 看进度 → 简单问答）。
驾驶舱是 `/lab` 的深度扩展，共享同一套后端服务和数据。
路径：`/lab`（冒烟）→ `/lab/cockpit`（驾驶舱）。

## 7. 成功标准

驾驶舱建成后，应能回答以下问题：

- [ ] 上传一份新的 Word 制度文档，3 秒内看到清洗动了什么、切块切在哪里
- [ ] 输入"住宿报销上限"，看到向量检索和关键词检索分别返回什么、差异在哪
- [ ] 看到 AI 回答中每句话的依据，无依据的标红
- [ ] 跑 42 条评测集，按文档类型看到哪类文档是短板
- [ ] 打开仪表盘，看到哪些文档从未被检索到（僵尸文档）
