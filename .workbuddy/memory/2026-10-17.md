**挖到的核心规律**（详见 `docs/wps-dingtalk-ui-reverse.md`）
- WPS 自家设计系统叫 **KD（金设计）**：12 色系 × 10 阶色板 → `CommonThemePalette` 语义层（text/icon/line/fill/background 五组角色）→ 组件层。
- 色阶**算法生成**：H 全程恒定（blue 217° / red 0°），L 递减不等距（`-4,-9,-11,-9,-13,-5,-9,-8,-5`，5→6 差 13 最大），S 中段下凹（100%→76%→83%）。红蓝两系同构即铁证。
- **icon 比 text 浅一阶**（icon-primary=gray-9 vs text-primary=gray-10）；**文字比图标深一阶**（text-success=green-7 vs icon-success=green-6）。
- 状态是相邻阶：hover 浅一阶、pressed 深一阶，不另造色。
- 尺寸：圆角 2/4/6/8/12（控件 4~6），字号基准 14，行高 22；阴影**越大约淡**（small 10% / middle 14% / large 8% + blur32）。
- 布局：**45px rail + 259px 面板 + 内容**，列表行高 **64px**；钉钉单栏 130 + 详情 190、行高 34。

**EasyShare 病灶**（`frontend/src/style.css:1-21`）
- `--blue:#007aff` S=100%（WPS 76%）→ 大屏刺眼
- 中性灰 `#1d1d1f` H=240 S=2%，**纯灰且色相与品牌蓝 211° 差 29°** → 发死；WPS 用 H≈220 S=14~31%，且越浅越去饱和
- 选中态用渐变实心块、背景叠三层渐变+`blur(34px)` 毛玻璃 → 层次不可控

**产出**

## 第八轮：回收站 30 天保留期（本轮已修正上一条）

用户确认「回收站能还原，但只留存 30 天」。**查证：代码里根本没有 30 天清理逻辑**，`es_file` 的 recycled 行无限期保留、对象也不清 —— 所以不能直接改文案，得先把规则做出来。

**后端**
- `DriveSchedulingConfig`：`@EnableScheduling` 独立成类（platform-drive 是可选模块，不挂启动类）
- `RecycleJanitor`：每天 03:30 扫 `state='recycled' AND deleted_at < now-30d`，逐条 `purgeFromRecycle`（对象+行一起清）；单条失败只记日志，下次调度重试（幂等）
- `purgeExpired(LocalDateTime now)` 显式收「以哪个时刻为现在」，便于测边界

**常量单源**：后端 `RecycleJanitor.RETENTION_DAYS=30` ↔ 前端 `types/core.ts RECYCLE_RETENTION_DAYS=30`，两边注释都写明「改一处必须改另一处」；文案不硬编码天数。

**文案**：删除确认 →「可在回收站还原，回收站保留 30 天」；回收站空状态 →「保留 30 天，期间可随时还原」。

**已知边界**：清理任务无单测（要 mock MyBatis selectList，逻辑是查+循环调用）；多实例会重复调度（幂等，仅日志噪音）。

## 第十一轮：文件分享（长效可撤销）｜提交 d3c69d2

**核心判断**：预签名 URL 的致命缺陷是**不可撤销** —— 发错了只能等它过期。企业场景里「想收回」是高频需求，这才是分享层存在的理由。

**数据层**：`es_share`（token base62 22 位≈128bit / expires_at / revoked / visit_count）。
`file_name`、`file_size` 是**创建时快照**：文件后来被删，分享列表仍要能说明这行是什么。

## 第十七轮：v0.3.0 外网地址 + macOS 链接错误（用户拿到 CI 日志后）

### ① v0.3.0 客户端连的是 localhost（发布包废掉的原因）

**根因不在发布脚本，在 CI**：v0.3.0 由 tag 触发 GitHub Actions 构建，而两个 workflow 里**完全没有 ldflags 注入**（grep `.github/workflows/*.yml` 一个都没有）。本地 `scripts/build.ps1` 支持 `-PlatformUrl`，但 CI 走的是裸 `wails build --nsis`，绕过了它 → `defaultPlatformBaseURL` 保持源码默认 `http://localhost:8090`，同事装完连自己电脑。`strings build/bin/easyshare.exe` 验证确实硬编码。

### ③ macOS CI 链接失败真因（卡了两轮的那个）

日志红字：`Undefined symbols for architecture arm64: "_OBJC_CLASS_$_WailsContext"`（Xcode 26.6）。

`meetings_capture_darwin.m` 用 `@implementation WailsContext (MeetingMediaCapture)` category 给 Wails 的 WKUIDelegate 补麦克风授权方法。**category 在编译期生成对 `_OBJC_CLASS_$_WailsContext` 的符号引用，而 WailsContext 由 Wails 内部包（`internal/frontend/desktop/darwin`）编译，那个符号不进最终链接产物** → 链接期找不到。

**修法**：`@implementation category` → `__attribute__((constructor))` + `objc_getClass("WailsContext")` + `class_addMethod`。运行时按字符串查找，**零链接期依赖**；类由 main 引用 Wails 必然先加载，查找必命中。附带好处：`class_addMethod` 在已存在时不生效，将来 Wails 自己补上该方法不会被覆盖。

**旁证**：`panel_darwin.m`（ESPanelWindow / ESPanelController）与 `tray_native_darwin.m`（EasyShareTrayController）用的都是**本项目自定义类**，无跨包依赖 → 全仓只有这一个文件有此问题。

**踩坑**：主包 `.m` 里不要 import/引用 Wails 内部包定义的类；需要就用 runtime API。
