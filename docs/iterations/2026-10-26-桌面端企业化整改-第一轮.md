# EasyShare 桌面端企业化整改 · 第一轮

> 用户实机反馈四条：插件页裸奔、会议听记连 127.0.0.1:8000、账号头像昵称不能改、缺细粒度权限。
> 本轮只做前两条（用户拍板范围）；后两条另起迭代。

## 用户问题

- 打开「插件中心 → 剪切板」，插件页是一列裸文本（`全部记录`/`收藏`/`本地记录 0 / —`）加底部一块黑色半圆，看起来像"扩展装坏了"。
- 「会议听记」连的是 `http://127.0.0.1:8000`，可这台机器的控制面配的是 `http://47.96.128.231:11054`；日志里连续 `无法连接知识服务器`。

## 目标

1. 主窗口插件页正常渲染（样式、脚本、SDK 全部生效），dev / 生产 / 快捷面板三条路径一致。
2. 员工机器上的知识服务地址由控制面说了算：地址不一致时旧会话失效、引导重新登录，而不是继续用本机地址发请求。

## 非目标

- 不改插件包格式、不改插件权限模型、不动商城发布链路。
- 不做个人资料编辑（头像/昵称）与细粒度权限——下一轮。
- 不引入"本机地址覆盖控制面"的旁路。

## 设计决策

### 1. 插件页改走 loopback 静态源

事实（排查结论，供下次省事）：

- 插件文件没坏。仓库 `plugins/clipboard/` 与 `%LOCALAPPDATA%\EasyShare\plugins\clipboard\` 四个文件字节一致；应用内 loopback 服务对 `index.html` / `style.css` / `/plugins/_sdk/eshare.js` 均返回 200 且 MIME 正确。
- 同一个 iframe（`sandbox="allow-scripts"`）指向该 loopback 源时渲染完全正常（实测 111 条 CSS 规则生效、`body` 被脚本补上 `mode-full`）。
- 走 Wails 自定义源（`http://wails.localhost`）时只有入口 HTML 到达，`style.css` / `app.js` / SDK 全部丢失。裸 SVG 因此按默认 300×150 黑圆渲染，被 iframe 圆角裁成底部半圆。

方案：`App.PluginHostBase()` 返回面板已在用的 loopback 静态服务基址（`127.0.0.1:0` 随机端口，复用同一 `assetMux`），前端 `PluginHost` 拿到基址后再挂 iframe。`startPanelServer` 改为幂等，面板、搜索表面、插件页三处共用同一次监听。

放弃的替代方案：给 iframe 加 `allow-same-origin`（削弱沙箱，且不解决自定义源问题）；把 CSS/JS 内联进 HTML（治不了后续插件）。

### 2. 知识服务地址以控制面为准

事实：`127.0.0.1:8000` 没有任何硬编码，二进制里 0 次出现。真正生效的是 `knowledge.json` 里的 `serverUrl`；控制面登记值只用于"未配置时预填登录框"，`configured=true` 时直接跳过，旧会话永远赢。

方案（`App.reconcileKnowledgeSession`）：

- 触发点：账号登录成功、启动恢复会话、管理员保存服务配置。
- 登记值存在 → 权威；与会话地址不一致 → `KnowledgeLogout()` + 发 `knowledge:target-changed` 事件。
- 登记值缺失 → 只在「控制面非回环、会话指向回环」时用同主机推导值纠正；控制面本身是回环（本地联调）不干预。
- 未登录账号控制面时完全不动（读不到登记值，也不该改用户的联调配置）。

放弃的替代方案：启动时静默把会话地址改成登记值（令牌属于旧服务，改了只会 401）；允许本机长期覆盖（企业统一治理会漏，用户明确选择控制面权威）。

### 3. 冷启动不再把有效会话显示成登录页（真机点验时暴露）

事实：`App.Startup` 先 `EnsureCore`（冷启动几百毫秒）再 `restoreAccountSession`，而前端挂载更早，`useEasyShare` 挂载时只调一次 `CurrentUser()`——那一刻 `accountSession` 还是 nil，返回 `loggedIn=false`，之后再不重取。日志里 `restored account session for admin` 与界面停在登录页由此同时出现（2026-10-27 冷启动复现）；热启动 Core 已就绪时不触发，所以 10-20 的验证没暴露。

方案：抽 `syncAuth()`，除挂载时调用外，在 `initialize()`（等到第一次成功 snapshot，即 Core 客户端已安装）后再取一次。会话文件读取发生在客户端安装之后几毫秒内，snapshot 往返更慢，因此第二次必然读到恢复后的会话。


## 兼容与迁移

- `config.json` 无新增字段；`knowledge.json` 可能被清空一次（地址对账），用户需重新登录知识服务——预期行为。
- 新增 Wails 绑定 `PluginHostBase`、新增事件 `knowledge:target-changed`；旧前端不认识事件名时只是不刷新。
- 新增 `ServiceEndpoints.knowledgeUrlAuthoritative` 字段，老 Core + 新前端时该字段为 `undefined`（前端按 false 处理，不影响登录）。
- loopback 监听端口每次启动随机，不落盘、不留残留。
